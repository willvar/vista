# 消息撤回和编辑

[English](./message-revert.md)

打开编辑只进入临时输入框，不修改历史。发送编辑后的消息或确认撤回时，在所选用户消息的发送时刻建立新分支。同次执行中更早已保存的回复也会保留。撤回只把原文和附件放回新分支的输入框，不自动发送。

用改动消息下方的左右箭头切换该消息的版本。如果消息不在当前可见范围，向上滚动找到它。新分支尚未发出替代消息时，箭头在输入框上方。切换会保留各分支自己的草稿，不停止原分支工作，也不迁移排队输入。同一会话的所有分支最多同时运行一个前台任务。已经执行的工具、主机文件改动和远程副作用不会撤销。

左栏每个会话只有一行，显示各打开分支的活动。点「等待你回答」等状态，可以直接前往需要处理的分支。
用版本箭头主动切换，会在 Vista 服务上按用户保存偏好的分支。在同一 Vista 服务中选用同一用户，从左栏或「管理会话」进入时，各设备都会使用这个偏好。它不会把其他已打开的标签页切过去。打开分支网址、刷新页面或点击活动提示，都不修改偏好。
偏好的分支没有打开时，优先进入已打开的原分支，否则进入另一个已打开的分支。不自动重开已关闭的分支，也不覆盖原偏好。整个会话已关闭时，仍可通过「管理会话」重新打开。

## 存储和上下文

分支保存稳定 ID、父分支和原始消息标识。每个分支使用独立持久会话流，网页和 Worker 读取同一份分支历史。共同历史只存一份。分支按发送时刻引用原有历史，沿用原消息和执行 ID；新记录才属于新分支。附件、已完成的工具输出及回放数据也只共享引用。仅当压缩检查点及其覆盖范围都在分叉点之前时才继承检查点。实时队列、续行状态和进程归属仍属于原分支。边界及以后的事件和消息不进入新分支。

`GET /api/sessions/{id}/branches` 列出各分支地址、来源消息，以及分支自身首条用户消息（如已存在）。响应包含消息标识和序号，不包含消息正文。`PUT /api/sessions/{id}/branch-preference` 把指定的已打开分支设为该会话的偏好。有已打开的派生分支时，会话列表快照包含有界的 `branchGroup` 入口和状态摘要，不改变分支自己的执行、已读状态。撤回返回新会话，原地址不变。还有派生分支时拒绝删除原会话，避免连带删除。以前破坏性撤回删掉的内容不能事后恢复。

## 验证

- `internal/store/branches_test.go`：保留原历史、单前台执行和压缩边界隔离。
- `internal/server/revert_test.go`：保留附件归属并恢复输入数据，不修改文件。
- `web/e2e/message-revert.spec.ts`：编辑、撤回、插话、运行中分叉和已发生的文件改动。
