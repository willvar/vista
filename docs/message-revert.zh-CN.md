# 消息撤回与编辑

[English](./message-revert.md)

撤回和编辑共用同一条会话回退链路，边界是所选用户消息的发送时刻，
不是整个 run；同次执行中已经提交的较早答复可以保留。

- 撤回恢复发送前的会话，原文和附件回到输入框，不自动执行。
- 进入编辑只读取草稿，不停止任务或改变历史；取消恢复进入编辑前的草稿。
- 编辑提交时，通过一次带 `replacesMessageId` 的发送请求先回退再启动新执行。
  若回退成功而新执行未能启动，修改后的草稿保留，作为普通消息重试。
- 回退会停止该会话的 Worker、子任务和后台进程，确认进程树结束后才截断历史；
  已打开的会话随后启动新 Worker。其他会话继续工作。
- 回退与同会话的发送、压缩、队列启动串行处理，未投递的旧输入不会自动续发。

## 文件与工具副作用

仅回退会话及模型上下文，已经发生的文件新增、修改和删除全部保留。
数据库、远程服务等其他工具副作用也不撤销；后续执行面对文件的当前状态。
撤回确认弹框和编辑提示明确说明文件改动保留。

文件与 shell 工具直接执行原有操作，不为撤回建立文件副本或扫描工作目录。
`write_file` 仍通过预期 SHA-256 校验及原子写入防止覆盖已变化的文件。

## 有效上下文

同一 SQLite 事务删除边界及之后的正式消息、模型历史、输出分块、
上下文压缩检查点及子任务报告引用，恢复较早的检查清单与待答复问题，并丢弃旧队列。
被回退附件的会话所有权随有效消息更新；浏览器已经取回的原件用于草稿。
历史读取、模型输出读取和资源列表都无法从原 ID 找回被回退的内容。

同次执行被部分保留时，剩余记录明确收尾为中断，不因删除终态事件而显示为运行中。
会话标题和模型选择是独立的用户配置，不随消息回退；迟到的自动标题只允许写回其原始
首条用户消息仍存在的会话。

`conversation_reverted` 使用原最高事件序号之后的新序号，SSE 序号不复用。
网页在该事件或回退响应后重新加载有效历史，取消旧请求、清空输出缓存，保留当前草稿，
并继续使用会话代次屏蔽迟到响应。操作入口属于消息操作区，与虚拟滚动共用现有消息行。

## 验证

- `internal/agent/tool_shell_linux_test.go`：包含特殊文件的目录内正常执行前台和后台命令，
  命令失败、信号退出仍保留真实输出、错误状态与文件改动。
- `internal/store/revert_test.go`、`internal/server/revert_test.go`：文件改动保留、上下文与输出截断、
  同 run 插话、单调事件序号、附件、资源所有权、待答复问题、任务报告及迟到标题。
- `web/src/composables/useConversation.test.ts`：编辑取消、重新发送、附件回填、
  跨标签页回退及快速切换会话。
- `web/e2e/message-revert.spec.ts`：独立 Chrome 的桌面与手机界面，真实 Worker 的文件改动保留、
  外部修改、编辑、撤回、运行中回退、后台进程和插话边界。
