# 产品行为与受众

[English](./product.md)

Vista 是带浏览器界面的通用型智能体。用户描述目标、提供相关路径或附件，与能够调用工具的模型协作。一个可执行文件包含 Go 服务、会话 Worker 和内嵌的 Vue 界面。

## 受众与设计基线

Vista 主要面向能独立使用和配置电脑或手机常用软件的用户：

| 用户类型 | 典型能力 |
| --- | --- |
| 熟练日常使用 | 能管理文件与文件夹、安装软件、调整常用设置，并搜索解决办法。 |
| 进阶工具使用 | 在此基础上，会组合工具、扩展、批处理或简单自动化，能按照说明完成陌生配置。 |

使用 Vista 不以掌握编程、命令行、API 或服务部署为前提。

产品变更遵循以下原则：

- 通过清晰的默认值和指引，让具备日常软件操作能力的用户独立开始使用。
- 逐步展示设置，让用户能按照说明扩展模型、技能和 MCP 工具，不增加日常操作负担。
- 用用途、收益和代价解释陌生控件。
- 能自动更新的视图不保留常规刷新按钮；自动检查频率较低，且用户确有立即检查需求时保留手动入口，例如模型目录检查更新。
- 围绕任务与协作描述产品，不把部署位置限定为用户自己的电脑。
- 为更熟练的用户保留配置空间。操作能力和学习意愿分别考虑，桌面端和手机端也分别判断。

## 会话行为

- 首次使用先在设置中连接模型服务商。内置连接封装服务商配置；自定义连接明确选择 API 格式及认证。实际可用模型取决于所连接的服务和账号。
- 第一条消息发送时才创建会话及 Worker。打开的会话在准入和健康检查允许时保有常驻 Worker。切换页面或关闭浏览器不停止工作；关闭会话停止其 Worker 和受管工作，保留历史。删除会话移除所属会话数据。
- 侧栏会话菜单提供重命名、二次确认后关闭和二次确认后删除。侧栏、会话顶部和会话管理中的标题均在原处编辑，失去焦点后保存。
- 置顶会话在侧栏和会话管理中排在前面。侧栏的置顶组和非置顶组内部按创建时间倒序，时间相同时按 ID 倒序排列；会话管理在各组内应用所选排序。
- 会话管理中，关闭有正在执行的任务或后台进程的会话时需要二次确认，批量关闭同样如此。空闲会话可从会话管理直接关闭。
- 同一会话的主线程顺序执行，不同会话、子任务和工具可以并行。执行中发送的消息会在下一决策边界交给智能体，在下一次模型请求前加入上下文。取消或失败会暂停未投递输入；执行停止后新发消息可开始新工作，不会自动恢复旧的暂停消息。
- 重启恢复打开会话的 Worker，将未完成工作记录为中断，不续跑中断的模型请求，也不重放工具副作用。
- 正文、执行过程、提问和用量归属于原消息。执行细节按事件顺序直接展示为次要消息，包括子智能体活动，不再折叠整个过程或单个智能体。较大的工具输出及子任务报告按需读取。执行期间，当前动作、耗时和最近活动固定在消息输入框上方，不随历史消息滚动。进行中的任务清单通过会话右上角的 List check 图标点击弹出；没有进行中清单时不显示图标。待处理输入紧邻输入框上方，位于执行状态下方。完成、失败或停止后，最终清单成为本轮历史中可复制的消息体，右上角清单入口随之关闭；新一轮执行不沿用上一轮清单。侧栏分别提示前台执行、仅后台活动、未读回复、待回答、输入队列暂停、Worker 不可用和执行失败。
- 查看错误后会清除其未读提醒，会话仍保留执行失败状态。待回答的提问、暂停的输入队列和不可用的 Worker 仍会提示需要处理。
- 模型服务暂时不可用时，可对同一请求最多重试三次，不会重复执行已完成的工具。等待过程可见、可停止，刷新页面后仍可恢复显示。已识别的认证、额度、协议错误，以及已经开始输出后的故障仍会结束执行。失败后点击“继续执行”，会在原会话中发送继续任务的消息，沿用保留的历史，并保留未发送的草稿。重试条件和等待上限见[模型请求恢复](./architecture.zh-CN.md#模型请求恢复)。
- 模型可以正常结束而不再返回文字，例如已通过工具交付结果。Vista 仍会处理待发送消息、收集必须等待的子任务，并提示执行已结束但未返回文字；不会添加智能体回复，也不会据此认定任务成果正确。请求和协议错误仍按失败处理。
- 自动选模提供快速和质量模式；手动选择连接、模型及可用推理档位。执行中修改设置从后续执行生效。
- 自动生成会话标题默认开启，可在个性化中关闭。开启时，首次标题由一次独立模型请求生成，不带工具或显式推理强度，标题请求可独立失败。关闭时，新会话使用本地化默认名称并附上创建时间，例如“新会话-20261025174143”；时间按客户端所在时区显示，格式为年月日时分秒。已有标题和手动命名的标题均保留。

运行时的归属关系见[架构](./architecture.zh-CN.md)和[进程生命周期](./process-lifecycle.zh-CN.md)。

管理会话在全部已保存会话中搜索和筛选，每次读取一页摘要。默认每页 10 条，可切换为 20／50／100 条；批量选择仅作用于当前页。
状态筛选同时展示全部、已打开和已关闭的会话数量；列表滚动时，搜索、筛选和分页保持可见。
点击会话标题或信息区域进入会话，已关闭的会话会先重新打开。置顶和行菜单独立操作；菜单可重命名、关闭、重试不可用的 Worker，或二次确认后删除。
列表工具栏提供多选，以及创建时间、最近更新的双向排序，默认创建时间由新到旧。先对所有匹配会话排序，再分页，置顶会话始终在前。
最近更新取最后一条持久化会话事件，包括消息、执行记录和标题变化；空会话使用创建时间。已读、置顶、打开或关闭不会改变该时间，行内时间跟随当前排序字段显示。
点击“多选”进入批量选择模式，点击会话行即可勾选，操作栏按所选会话展示适用操作。
修改搜索、状态筛选、排序、页码或每页条数会清空选择；点击“完成”退出选择模式。

## 上下文与资源

已完成的模型轮次和工具结果可供后续消息与 Worker 重启后继续使用。只有上游明确的上下文超限证据才触发自动压缩，并重试失败请求。会话右上角的压缩图标在悬停时显示保留上下文的词元估算；点击后先确认，并说明自动压缩及压缩的利弊。手动压缩在空闲时共用检查点机制，不自动发送或继续执行。估算不是累计用量或模型容量百分比。见[上下文压缩](./context-compaction.zh-CN.md)。

图片以共享原件文件保存，由会话持有引用。新附件或显式资源读取激活下一次受支持请求的视觉输入，历史图片不自动重复发送。关闭会话保留所有权；删除会话释放关联，完全无引用的文件可手动清理。见[资源](./resources.zh-CN.md)。

关于 Vista 提供内存预设，以及总预算、单会话进程和同时执行数的自定义限制，并显示实际驻留占用。达到预算时拒绝新的高开销操作，Worker 超过自身限制时中断该会话。这是软保护，不是操作系统内存硬上限，外部工具进程另占内存。

编辑和撤回已发送消息仅回退会话及模型历史，文件、shell 副作用和远程改动仍然保留。见[消息回退](./message-revert.zh-CN.md)。

## 个性化与扩展

- 全局提示词位于用户配置根目录的 `AGENTS.md`，在执行开始时读取。文件工具自动检查目标路径，shell 工具检查工作目录内适用的局部规则。没有新规则需要读取时直接执行；发现新增或变更规则时，模型须先读取，再重试或调整操作。作用范围内更近的规则优先，用户当前明确请求优先于默认规则。
- 记忆保存跨会话的明确长期偏好。用户从个性化打开「管理记忆」二级弹框，查看简短预览、编辑完整内容或确认删除。弹框默认每页读取 10 条，可切换为 20／50／100 条。仅主智能体能调用 `memory`，子智能体继承偏好快照。删除单个会话不删除记忆。
- 最大委派层数默认为 1，范围 0–8；0 禁用子任务委派。它是上限，不是要求模型固定创建这些层。required 任务的报告在最终提交前自动到达，等待中的父任务仍可处理用户输入；best-effort 和 detached 的生命周期不同。
- 系统技能内置于 Vista，设置中可只读查看，随 Vista 更新且不释放到用户目录。当前内置的 `vista-guide` 用于配置和排查 Vista。用户将自己的、包含 `SKILL.md` 的技能文件夹放入配置根目录的 `skills/`，设置列表会自动更新。每次执行带入系统技能和已启用用户技能的名称、简介、路径及来源，完整正文及配套文档按需读取。简介遵循 Agent Skills 的 1024 个 Unicode 字符上限。技能编辑器通过目录树访问现有文件：可编辑 UTF-8 文本、预览常见图片，其他文件仅显示文件信息。桌面并排展示目录树与文件，移动端从目录树进入文件并通过返回按钮回到目录。切换文件保留草稿，关闭时确认放弃修改，保存时拒绝覆盖已被外部改动的版本。内置系统技能始终只读，编辑器不提供单个文件的新建、重命名或删除。
- MCP 通过本地 stdio 或远程 Streamable HTTP 提供工具，有启用／禁用控制及连接独立凭据；不提供 MCP 的资源、提示词、sampling 或 elicitation。
- MCP OAuth 通过手动提交回调完成：打开或复制授权链接，完成授权后将完整回调地址粘贴到同一个 Vista 弹框。不要求回调页面成功打开，也不启动自动回调监听器。授权五分钟后过期，关闭弹框将取消。回调链接包含短期授权信息，不应发到聊天或日志。Codex 和 Copilot 仍使用设备码登录。
- MCP 和技能设置可通过读取、选择、确认三个步骤导入 OpenCode v1/v2 配置，保留已有条目。技能复制完整文件夹，包括辅助文件和二进制资源；MCP 保存兼容配置，导入后异步连接已启用的服务。不支持的条目会显示原因，见[导入约定](./architecture.zh-CN.md#服务商与工具)。
- 网络查询分别配置搜索和网页读取服务、顺序、密钥及首次输出长度。搜索返回来源和摘要，网页读取通过 Jina Reader 或 DeepSeek 获取已知公开 URL 的内容。

## 配置编辑

设置与「关于 Vista」为下列七个配置分区统一使用 JSON Forms；智能体编辑器也包含 `AGENTS.md` 中的全局提示词。标量、枚举选项、对象和列表字段复用 Vista 控件。不再提供 JSON 原文编辑或模式切换。经过 Schema 校验的表单草稿须明确点击「保存更改」；无效字段值会阻止保存。既有业务分组将说明、示意图和相关控件放在一起；JSON Forms 负责渲染，不代替页面决定分组位置。搜索／读取服务列表显示固定名称，仅可上下移动，不是逐行替换服务。Schema 及业务校验在实际字段上显示具体原因和可见错误边框，不使用泛化的“突出显示”提示。个性化保持全局指令、记忆、带示意图的委派层数、自动标题这一顺序；分组保存仅提交自己的变化字段，自动标题保留直接切换行为。预览限制按 UTF-8 字节数计算，0 表示不限制。

设置视图收到变化后的值时，表单会保留正在编辑的草稿，包括无效字段值，并在重新载入当前值前阻止保存。重新载入会在丢弃草稿前要求确认。这是本地草稿保护：只有服务配置还会在保存时检查服务端对紧凑 `server` 分区计算的 SHA-256 修订号，而非整个文件的修订号，因此其他分区变化不会引起冲突。其他设置保留各自原有的保存行为。

表单只包含各类型的可编辑字段，不接收完整 `config.json` 根对象或 `key.json`。新输入的凭据使用遮罩、只写的表单控件；已保存的凭据值不会返回表单。服务商选择、模型发现、OAuth 和导入保留原有流程与类型化 API。Schema 渲染器统一替代普通字段和密码／请求头输入，不再维护并行手写表单，同时保留脱敏、留空复用及显式清除行为。

配置根目录有三个固定的用户配置文件名：主配置 `config.json`、静态凭据文件 `key.json`，以及可选的全局 `AGENTS.md`。两份 JSON 均位于私密配置根目录，文件权限为 `0600`（支持 Unix 权限时，根目录为 `0700`）。主配置必须包含整数 `version: 2`，七个原始 JSON 分区均可省略。在全新空根目录内，Server 启动或显式写入可以初始化当前文件；这是初始化，不是转换旧状态。缺失分区沿用原有默认值或环境变量回退；存储及凭据拆分保留显式 `null`、空值与缺失之间的区别。各分区的类型化校验器和 API 仍负责判定有效值及其行为。

| `config.json` 中的分区 | 用途 | 仅供启动迁移的旧文件 |
| --- | --- | --- |
| `server` | 已保存的监听端口，与当前运行的监听端口区分 | `server.json` |
| `capacity` | 内存预算及同时执行数限制 | `capacity.json` |
| `agent` | 委派深度及自动生成会话标题 | `agent-settings.json` |
| `search` | 搜索／网页读取服务、顺序及输出预览限制 | `search.json` |
| `userAgent` | HTTP 客户端身份设置 | `user-agent.json` |
| `models` | 模型连接及模型设置 | `models.json` |
| `mcp` | MCP 服务定义及连接设置 | `mcp.json` |

`key.json` 必须包含整数 `version: 1`，其中的 `entries` 对象将不透明引用映射到 `{section, owner, values}` 凭据包。主文档中的受管模型记录、MCP 记录或 `search` 对象通过 `credentialRef` 引用相应凭据包。归属使用稳定身份，不取自显示名称或数组位置；引用／归属字符串不是供用户编辑的标识。

| 分区 | 保存在 `key.json` 的静态字段 |
| --- | --- |
| `models` | `apiKey`、`accessToken`、`authToken`、`appCode`、`headers` |
| `mcp` | `token`、`clientSecret`、`headers` |
| `search` | `apiKeys`、`jinaApiKey`、`deepseekFetchApiKey` |

自定义请求头的值采取保守处理：整个 `headers` 对象迁出，而不是只迁出名称类似认证字段的请求头。公开的 `clientId`、路由和身份设置留在 `config.json`。SDK 管理的 OAuth 账号、刷新令牌和登录目录仍独立保存，不迁移 OAuth 令牌，也不重新设计授权流程。

这仅是文件隔离，不是加密，也不集成系统密钥环或云 KMS。密钥文件仍为明文，私密权限不防范同一用户身份下运行的进程。主文件仍可能暴露内部地址、项目／账号标识，迁出凭据并不意味着可以直接公开分享。备份可能保留旧明文凭据；此方案不承诺安全擦除，也不自动清理或恢复旧身份。

`AGENTS.md` 仍是独立的全局提示词文件，包含在智能体编辑器中，迁移不改动它。上表中的旧 JSON 文件名仅供启动迁移使用，不是其他保存位置。一次性转换专属于 Server 启动：先取得实例锁，再在应用设置加载前处理。没有主配置时才接受这七个文件，或升级此前内联凭据的 `config.json` v1。持有共享配置锁时，收集实际来源字节，校验 JSON 与大小限制、准备转换，并在 `.config-backup-<time>-<id>/` 内保留并校验含 `SHA256SUMS` 的私密逐字节备份。备份包括适用时的 v1 `config.json` 和已有 `key.json`，不限于旧文件名。先发布密钥、后发布主文件引用，校验已发布的双文件及所需持久化后，仅移除未变化的旧版来源原文件。v1 主文件由当前主文件替换，不会在之后删除新主文件。私密备份继续保留，不自动恢复。见[存储约定](./architecture.zh-CN.md#统一配置存储)。

已有 `config.json` 始终是唯一来源，v1 升级时也一样：遗留旧文件会被忽略，不会合并回去，即使对应分区缺失也不例外。已有当前格式主文件后，后续启动只校验当前格式及引用的密钥；健康启动不扫描旧路径、不导入旧数据，也不新建迁移备份。JSON 无效、版本缺失／不受支持或凭据引用无效／引用的密钥条目缺失时按失败关闭处理，不重新导入，也不回退旧文件、内联密钥或备份，更不会自动重置；分区校验保留原有的类型化行为。旧版二进制不得打开同一个已迁移的配置目录。账号授权目录及 OAuth／登录快照不改动，也不自动恢复旧账号身份。

正常读写仅使用当前 `config.json` v2 和 `key.json` v1，不提供运行时旧数据或旧凭据回退，库的首次写入也不迁移。正常访问旧版或尚未迁移的数据时，会提示“启动 Vista 以迁移”（“start Vista to migrate”），而不是导入或复制旧值。显式写入仅可在前述全新空根目录情形下初始化文件，不转换旧状态。

这些是运行时的用户文件，与仓库源码及内嵌默认值分开。另有两个自动生成、不可作为配置编辑的文件：`omp-models.json` 保存下载的模型目录，`model-catalog-status.json` 保存目录更新状态及计划。两者不计入上述三个固定用户文件；账号独立授权、技能文件夹、SQLite／运行时 `state/` 和浏览器偏好也继续单独保存。

所有主配置／密钥文档写入方共用跨进程的 `state/config.lock`，在最新主文档中更新自身分区，保留其他分区和凭据，不以公开 API 投影覆盖根文档。凭据更新先暂存新的不可变引用及密钥条目，同时保留旧条目；再发布主配置引用；最后只移除本次已提交更新放弃的此前活动引用。已有的无引用条目（包括中断写入遗留条目）不会被盲目回收。每个文件的替换各自原子，但两份文件不构成单一原子事务。含密钥分区读取在读取密钥后再次检查主文档快照，遇到发布／裁剪竞态则重试；非密钥分区读取不加载密钥文件。

类型化设置 API 在内部解析凭据包，向运行时使用方提供完整分区，保留原有保存及运行时效果。此存储变更不为直接编辑文件新增全局热加载：智能体与客户端身份设置保留原有直接读取边界；缓存的模型、MCP、搜索及容量配置仍遵循既有重新加载／启动要求。

## 关于 Vista 与服务控制

「关于 Vista」按以下顺序展示：

1. 品牌、版本和简介。
2. 原有的模型目录与客户端标识控件。
3. 内存与容量设置。
4. 监听端口的服务配置。
5. 调试模式开关。
6. 全部重置，仅在调试模式下可见。
7. 重启 Vista，无论是否开启调试模式都可见。
8. 构建信息。

服务配置编辑监听端口，其值必须为 1 到 65535 的整数。
修改端口使用「保存并重启」，单独确认弹框会说明对当前任务和托管后台进程的影响。
保存前，独立的新实例先在配置的 IPv4 监听地址上绑定目标端口，并在启动过程中始终持有该监听套接字。预留失败时，当前实例和已保存配置均保持不变，表单保留草稿并显示错误。
修订冲突会取消预留，不覆盖其他编辑。与实际监听端口相同的值可保存而无需重启。
受理后，旧标签页保留新地址和「在新标签页打开 Vista」入口。直接 HTTP 访问沿用浏览器当前主机名并切换端口；HTTPS 代理访问保留公开来源，上游地址调整仍由部署方处理。重置后的导航采用相同的浏览器来源规则。受理不等于就绪；有时限、不携带凭据的就绪图片检查用于确认入口已提供 HTTP 服务。响应丢失和超时保持为未确认，绝不自动重复生命周期修改。
端口切换保留服务端数据。按浏览器来源隔离的偏好和草稿仍留在旧来源，Vista 不跨来源复制浏览器身份或登录状态。
普通启动优先级仍为 CLI `--port` > `VISTA_PORT` > 已保存端口 > 默认值。独立的「重启 Vista」操作沿用实际监听端口，不应用待生效的已保存端口。

「重启 Vista」使用普通次级按钮，每次操作都先打开确认弹框。
弹框在可用时展示活跃会话与托管后台进程数量；无法获取时明确提示未知，不按零显示。
警告会说明所有正在执行的任务和托管后台进程都会停止，未完成工作不会自动恢复或重放。
重启保留会话、资源、配置、浏览器偏好与草稿，以及配置目录和实际监听端口，不额外打开浏览器。
独立于旧 Server 的控制进程复用 CLI 重启流程：停止 → 等待实例锁释放 → 启动。
它加载同一可执行文件路径的当前版本，可启用已替换到该路径的新版二进制；不下载或安装更新，也不切换到其他 checkout。

确认后，弹框展示重启与重新连接的等待状态，不显示完成百分比。
只有共享状态 SSE 连接已经就绪，且收到属于新 Server 进程的 `instanceId`，才确认成功；HTTP 202 仅表示已受理，内部 App 或 SSE epoch 变化也不足以确认。
超时或响应丢失时，结果保持为未确认，不会自动再次发起重启请求。
「重试连接」仅重新连接以核对结果，不会再次发送重启 POST，也不会重放已中断的工作。

开启调试模式后，可在「关于 Vista」中二次确认并执行全部重置。重置会停止正在执行的任务、托管的后台进程及登录流程，再删除所有会话、附加资源、连接及凭据、用户技能、全局提示词、记忆和其他 Vista 配置。内置系统技能仍然可用。当前浏览器的 Vista 偏好与草稿也会清除，应用运行时在同一 Server 进程内重新启动，页面转到重开后的地址并返回首次使用页面。外部文件和服务（包括工具此前改动的文件）不会回退。监听端口恢复默认值，进程环境变量指定的端口仍然优先；上一次启动时使用的端口不再沿用。其他客户端的浏览器偏好和进程环境变量提供的设置不在重置范围内。

## 活跃与用量

设置 → 使用情况共用最近 7／30／90 天的周期，展示每日活跃／消耗趋势及星期／小时活跃热力图，按查看者所在时区显示。
打开的统计页会在本地整点／跨日时自动更新，无需等待新的活跃或用量记录。
热力图每格显示相同星期／小时在已记录日期中的平均活跃分钟；未活跃的时段计为零，开始记录前及尚未到来的时段不计入。
有点击、输入或滚动的分钟计为活跃；多个客户端的同时操作只计一次，页面闲置和后台执行不计入。
总消耗合计服务商上报的输入与输出词元，缓存和推理词元不重复相加，覆盖会话、子任务、压缩和标题生成。
成功但未上报有效用量的调用会单独说明，不计入总量；失败且未上报有效用量的请求不计入统计。
总量用熟悉的文本作粗略类比；悬停、点击或聚焦可查看原始词元数和简短说明。参照来源与换算规则见[使用情况统计](./usage-statistics.zh-CN.md)。
已有会话中保留的用量记录只补入一次；页面标明完整记录的起点，不补造历史交互活跃。
记录保留 90 天，与最长可查看周期一致；切换到更短周期不会缩短保留时间。
删除或撤回会话不扣减仍在保留范围内的消耗；在使用情况中确认重置统计，或完全重置 Vista，均会清除这些统计。

## 当前边界

Vista 默认监听所有 IPv4 网卡（`0.0.0.0`），接受任意请求 Host 和浏览器 Origin，并允许携带凭据的跨来源访问。可选启动环境变量 `VISTA_HOST` 可设为某个 IPv4 地址以收窄监听范围。访问限制由部署环境或反向代理承担；服务没有用户登录或按客户端隔离的数据，自身也不终止 HTTPS。工具使用服务用户权限执行，没有逐次工具审批或文件系统回滚。会话共享真实文件系统，没有固定项目目录，工具要求明确目标路径；文件写工具的乐观校验不覆盖任意 shell 写入。

图片附件目前支持 PNG、JPEG、WebP 和 GIF，每张最多 50 MiB。模型可通过 `read_resource` 导入本地图片，包括下载文件和已提取的帧；不支持音视频输入或自动提帧。没有内置 LSP、专用 Git 工作流或终端界面。模型／协议资料和本地模拟不能证明每个上游账号、模型均可使用，见[服务商](./providers.zh-CN.md)和[验证](./testing.zh-CN.md)。
