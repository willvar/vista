# 上下文压缩

[English](./context-compaction.md)

Vista 负责识别上下文超限，不通过模型 ID、OMP 目录、用量百分比或历史失败推测服务商真实窗口。

## 检测

[context_overflow.go](../internal/provider/context_overflow.go)只识别 HTTP 错误、SSE 错误及明确停止原因中的上下文／输入／提示词超限证据，形成类型化错误。嵌套中转错误和 JSON 编码的 `metadata.raw` 在有限深度内检查；诊断正文最多读取 128 KiB，读取期限为两秒。

显式证据规则改编自以下 MIT 来源：

- Pi 的 `overflow.ts`，版本 `b9ab2a6238d2c91cf0c6ebf836dfd05883f9db51`，见[许可](../licenses/pi/LICENSE)；
- OMP 的 `error/flags.ts`，版本 `f1ac114d8d3438bee43010aee559bfe720ba3224`，见[许可](../licenses/oh-my-pi/LICENSE)。

本地中转测试样本模拟 [New API](https://github.com/QuantumNous/new-api/blob/7de10f2c602b50122017556e8a09cb7c488c273c/service/error.go) 和 [One API](https://github.com/songquanpeng/one-api/blob/8df4a2670b98266bd287c698243fff327d9748cf/relay/controller/error.go) 的错误封装。
覆盖保留上游消息／代码、改写 HTTP 状态及 HTTP 200 JSON 错误等形态。

仅有 400／413／503、图片或字节载荷拒绝、泛化的 “too many tokens”、限流／额度／认证错误、输出词元参数错误、普通 `length`／`max_tokens` 结束、断连或用量超过目录值，都不触发压缩。assistant 正文不作为错误分类。未知失败正常停止并显示；中转彻底抹去原因或静默截断输入时无法可靠判断。

## 恢复与存储

自动恢复只在模型／工具决策边界运行，保留固定系统指令、当前执行原始任务、最新用户输入、未完成调用组和最新完整 assistant／tool 组。更早的完整组由当前所选模型无工具地摘要。
已完整读取且源文件哈希仍有效的项目规则保留原始 assistant／tool 配对，包括目录范围、分页偏移和原生回放状态。
未读全、已变化或已移除的规则不受此保护；文件操作仍要求实际请求中包含完整且有效的规则原文，摘要提到“读过规则”不能授权文件操作。
估算只在明确超限后用于划分摘要批次，不代表模型容量。

自动收集的子任务报告带本地 `RuntimeData` 标记。线上的角色仍为 system，但属于可压缩证据，不是固定指令；刚追加在最新工具组之后的报告也可摘要。标记随历史、检查点和模型／协议变化保留，不序列化到服务商 API。同一报告批次共享 16 KiB 答案／错误预览，保留截短标记及原报告引用；压缩后可通过 `read_model_output` 或 `await_agent` 补读。摘要保留任务身份和报告引用，将报告作为运行结果处理。

手动压缩共用摘要和检查点，也可摘要最后一个已完成答复，包括只有一组用户／assistant 消息的会话，但逐字保留最新用户输入。待回答问题未解决时保护最后一组。

首次摘要请求包含全部待压缩文本和已有摘要；只有上游明确报告上下文超限才减半文本预算，并将余量均分为固定数量的请求。
UTF-8 边界和整数取整不会产生只有几字节的额外尾段请求；模型及推理强度沿用用户选择。
每次尝试均以唯一轮次配对记录 `model_request`／`model_result`，标注 `purpose: "summary"`、结果、耗时及服务商提供的用量，包括失败和取消；诊断使用相同轮次。
词元统计仍沿用服务商调用入口的计数链路，这些结果记录不重复计入用量。
摘要提示词要求保留目标、约束、已有授权、已验证工作与副作用、待办、疑点及证据引用。
一次压缩最多 32 次摘要请求，包含被拒绝请求；摘要必须是非空 UTF-8 正文，最多 8 KiB，不含工具调用，压缩后上下文必须更小。失败不替换当前检查点。一次失败主请求最多尝试两次恢复压缩，成功模型轮次重置计数；已完成工具不重放。压缩期间到达的输入在下一决策边界处理。

不可变 `state/outputs/context-*.gob` 保存摘要、剩余消息、资源引用、工具配对及服务商回放字段，不存图片字节。原件仍在共享资源库并归会话所有。文件 sync 后，确认过的 `context_notice` 在事件日志提交引用与正式输入截止位置；丢失 ACK 不代表未提交，因此保留该文件。

主模型消息另行增量保存到不可变的 `state/outputs/history-*.gob`。模型轮次在本地工具启动前提交，每个工具结果完成后独立提交，包含错误和取消结果。`model_history` 只携带引用、轮次、片段／索引及词元估算；内容来自模型实际参数和可见结果，不是 UI 预览。不新增正式答复或重复计算用量，中间回复、question 调用和已收集报告也保留，子任务全文仍在自己的过程内。

question 保留原参数、call ID 及回放字段。表单提交在界面中仍为用户消息，其事件关联待答复调用；模型上下文只恢复一次，作为该调用的工具结果，首次回答后请求也如此。待回答问题跨重启、压缩及会话回退恢复，不标记为中断。普通新消息替代未回答问题时，先生成明确的未回答结果，再加入新输入。

新执行按事件顺序合并模型历史和正式用户输入，排除已保留轮次的正式 assistant 重复投影，包括插话前提交的答复；长最终答案保留全文。检查点通过事件序号和正式输入截止位置替代旧历史，防止重新追加旧工具。Worker 在记录调用后、记录结果前退出时，恢复明确的未知／中断结果，不执行工具。新执行与重启使用相同读链路，系统指令重新组装。切换协议、服务商、端点或模型时去除服务商签名，保留通用正文、资源引用和工具配对。

压缩不改写可见聊天及工具产物。仅新附件或显式 `read_resource` 为下一次请求副本加载原件，受模型图片能力约束；成功后只保留元数据和哈希，直到模型再次读取。切换纯文本模型不删除规范引用。被摘要省略的图片仍可通过 `list_resources`、`read_resource` 访问，见[资源存储](./resources.zh-CN.md)。

## 手动流程与界面

`POST /api/sessions/:id/compact` 接收可选的 `modelKey` 和 `reasoningEffort`，原子占用会话执行槽。执行中拒绝压缩，普通发送／插话或另一压缩不能重叠。手动成功后释放空暂停队列的状态，已有待发送输入仍暂停；不会产生新的用户输入、模型轮次或启动队列。取消、Worker 丢失和重启通过相同终态事务释放执行槽，检查点提交是成功边界。

`GET /api/sessions/:id/context` 及有序 `context_status`／`context_notice` 提供进度和结果。前端比较事件序号、保留会话取消保护，不让迟到 POST 恢复旧状态。界面没有容量、剩余词元或百分比；输入区显示压缩进度或失败状态，以及保留主上下文的词元估算，包含指令、摘要、消息和工具内容。`context_usage` 和压缩通知更新估算，`GET /api/sessions/:id/context-usage` 在最近事件窗口外恢复；空闲时用下一请求相同组装链路重算，包含已完成或中断执行的工具历史。它不是累计请求用量或自动压缩阈值。

自动和手动压缩成功后，输入区状态收起，已提交的摘要按事件位置显示为正常智能体消息，支持 Markdown、复制，并展示实际压缩模型及其词元用量／调用明细，执行详情中不再重复展示。消息分页和快照从现有 `context_notice` 生成这条展示记录，也能恢复最近事件窗口以外的摘要；事件回放使用相同的消息标识。这种展示不会增加模型请求或模型历史条目，也不重复计算回复用量、反馈或未读数量。
每条摘要仅关联本次压缩开始后的主智能体压缩调用；普通回复排除这些调用，子任务用量仍归属于对应回复。

手动成功、空闲、草稿及图片均为空时，placeholder 提供“继续”的 Tab 补全；激活会话聚焦可用输入框，Tab 只填入不发送。Shift+Tab 和没有补全的 Tab 保持正常焦点导航。较新用户消息消除提示，刷新后也如此。
执行或压缩失败后，保留可复制错误、“在新会话分析此故障”按钮，以及尝试手动压缩后继续的提示。
按钮按当前选模方式和界面语言发送诊断提问，附上原会话与执行 ID、错误以及有长度限制的最近消息摘录。
诊断文本中的标记分隔符经过转义，不会直接重放原会话历史；内置指南说明如何按需查看更多证据。
原会话和草稿保留；如果首条诊断消息被拒绝，新会话会保留提问草稿供重试。
