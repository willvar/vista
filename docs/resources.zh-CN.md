# 会话资源

[English](./resources.md)

Vista 将不可变原件保存在选定的本地或加密对象存储后端。本地固定路径为 `state/resources/<哈希前两位>/<完整 SHA-256>`。相同字节跨会话共用在用原件，保留的物理副本另计占用；原件不缩放或重新压缩。前端与 Worker 对 PNG／JPEG／WebP／GIF 原件统一限制为每张 50 MiB。`read_resource` 也能导入本地图片，包括工具下载的图片及已提取的视频帧；不支持音视频输入或自动提帧。资源库不包含项目工作目录、工具产物或进程日志。

生成的图片、视频原件共用现有后端、SHA-256 ID 和会话归属。生成的 MP4／WebM 原件上限为 128 MiB，上游链接过期后仍可通过资源 ID 读取。视频是产物，不作为消息附件或对话模型输入。工具等待原件归属提交后才报告成功。决策结果保存为工具产物，不写入媒体库。`list_resources` 列出媒体引用；`read_resource` 仍只向模型提供图片输入。

## 存储位置

「设置 → 存储空间」分别显示当前存储和已保存的配置。可以添加、编辑、测试或移除多套命名的 DOFS 配置；编辑表单填写 S3 兼容的 HTTP(S) 服务地址、Bucket、可选区域和前缀，以及访问凭据。保存新配置或测试连接都不会切换存储。通过「切换存储位置」选择已保存的名称或本地存储，再确认迁移。本地存储表示不引用任何 DOFS 配置。

要更换正在使用的服务地址、Bucket 或前缀，需添加另一套配置并明确切换；重命名和更新凭据不会迁移文件。选择对当前 Profile 的所有会话生效，不是浏览器或单个会话的偏好。本地目录不可选择；数据库、设置、锁、进程日志和项目文件不会迁移。字节存储层不区分资源来源或媒体策略，更改存储不会自动增加模型的输入／输出模态支持。

对象存储直接使用独立的 [DOFS](https://github.com/willvar/dofs) Go 后端，不依赖 FUSE，也不要求 PostgreSQL。每个已登记后端使用实例管理的独立 namespace，本地 DOFS SQLite 元数据位于 `state/resource-backends/`。对象采用 DOFS 分块 AES-GCM 加密，属于服务器托管加密，不是零知识存储。访问凭据和生成的主密钥由 `storage` 分区的私密 `key.json` 凭据包保存，不返回表单或共享状态。同一保存位置可以留空访问密钥以沿用已有凭据。测试不会保存表单或替换在用凭据；保存新的连接设置前会验证其可用性。存储请求使用既有「全局请求」网络策略，保留 SDK 的请求上下文、重试及连接清理语义。

不能移除当前配置或迁移中受保护的目标。移除未使用的名称不会删除任何文件，回收旧副本所需的物理身份、密钥和恢复记录仍保存在私密配置中。旧版当前或最近所选的 DOFS 位置会显示为已保存配置，不改变其物理身份或加密密钥。未迁移且没有待恢复测试的配置不参与资源占用统计。

哈希、传输及需要随机读取的远程下载使用固定缓冲区和私密 `state/resource-staging/` 暂存文件；临时副本仍需要本地磁盘空间，并在正常结束或启动恢复时清理。恢复对象存储资源需要 Vista 数据库、匹配的 DOFS 元数据、加密密钥和密文对象。应一致性备份这些本地数据，不能将对象存储单独视为会话备份。

## 引用与保留

SQLite 保存 `resources` 元数据、`session_resources` 所有权和有序的 `message_resources`／`queued_input_resources` 关联。原始文件名属于各引用，共享字节不会覆盖另一会话的文件名。图片二进制不存入 SQLite、Worker 命令或上下文检查点。

会话是保留根。关闭会话、撤掉或丢弃排队输入、压缩、取消、失败及重启保留所有权。删除会话级联删除关联，其他会话持有的共享原件保留。消息回退是另一例外：仅被撤销历史持有的关联会释放，不在该会话资源列表中继续暴露。物理原件仍在存储中，直到用户在存储空间手动清理完全无引用文件。没有自动回收或保留聊天同时剥离附件的操作。

更早的工具导入及补读记录在后续回退中保留对应所有权；编辑消息时，只额外保留本次明确提交且已属于该会话的图片引用。

新附件从引用加载到下一请求的临时副本，受当前模型视觉输入能力约束。成功后，后续请求只保留元数据和哈希；模型需要再次观察时显式调用 `read_resource`。纯文本模型看到元数据和省略说明，切换模型不自动重发历史附件或改写规范历史。

`read_resource` 必须且只能提供 `path`（本地图片绝对路径）或 `hash`（该会话持有的完整哈希）之一。按路径读取先复制原件到资源库再激活，源文件变化或删除不影响后续读取。

两个工具都在资源引用中返回会话持有的 HTTP `url`，回复可用 `![说明](url)` 展示图片；本地文件路径和 `file:` 地址不能用作浏览器图片地址。该链接复用现有的会话归属校验和原件下载路由，不改写此前已保存的错误路径回复。

摘要保留资源哈希。`list_resources` 使用哈希游标列出保留原件，`read_resource` 将获准原件作为下一次请求的视觉输入。即使摘要遗漏哈希，也可通过列表找回图片。运行时图片内容投影在完整工具结果组之后，不持久化伪造用户消息；单次请求激活状态不写入历史或检查点。当前请求撞墙恢复时保留待发送附件，成功前不会失去激活，也不会重新激活历史图片。子任务可用会话资源工具，但不自动继承父任务当前图片载荷。

## 磁盘操作与 API

发布时流式写临时文件、计算 SHA-256、sync 后重命名。跨进程锁覆盖发布至引用提交、读取，以及清理的最终引用复查和删除。事务失败可留下可清理文件，不留下指向半成品的已提交引用；读取校验大小及完整哈希。Server 使用固定大小缓冲区将原始上传流写入 `state/inputs/` 暂存文件。会话 Worker 校验并导入原件，等待 Server 确认所有权已提交后才返回引用。操作结束或中断后下次启动时删除暂存文件；已发布但未建立所有权的原件仍由用户手动清理。

只有 Worker 会将完整图片载荷加载到内存、组装含图片的模型请求，包括自动标题。远程读取和迁移使用私密暂存文件及固定缓冲区。Server 下载接口流式校验大小和哈希再返回原件；草稿与回退接口只返回引用。

浏览器先下载已发送消息的原图，再执行撤回，避免释放历史关联后无法将附件放回草稿。

- `POST /api/sessions/:id/resources?name=<文件名>` 接收原始图片请求体及图片 `Content-Type`，最多 50 MiB，要求会话已打开且 Worker 就绪；所有权提交后返回 `{hash, name, mediaType, bytes}`。
- 消息提交的 `images` 携带这些引用，消息 API 不接受 Base64 图片请求体。

- `GET /api/resource-storage` 返回异步操作和最近扫描；`POST` 的 `{"action":"scan"}` 或 `{"action":"clean"}` 返回 202 并发起操作，并发请求共用已有操作。
- 占用按实际文件去重，区分被引用及可清理数量／字节。清理在每次删除前复查所有权，报告数量和释放空间，结束后重新扫描。关闭设置不取消服务端操作，组件卸载会中止页面请求。
- `GET /api/sessions/:id/resources/:hash` 只向持有原件的会话提供内容，消息图片 URL 按有序附件读取。

## 迁移与回收

存储更改是持久化的后台任务，关闭设置不取消任务。复制期间原位置始终是唯一生效后端，运行中会话产生的新原件也继续写入原位置。按明文 SHA-256 和大小补复制，以不可变对象上传，并回读目标内容校验。发布通知只合并唤醒任务，通知或工作队列为空都不能证明已经同步。

最终检查取得跨进程资源发布锁，重新枚举源端原件及被保留的逻辑引用；目标的持久化已校验清单必须覆盖两者，才在一次 Vista SQLite 事务中提交新生效后端、递增的存储代号和迁移完成状态。最终临界区不进行远程传输、HEAD 请求或内容哈希。Worker 取得锁后才解析生效后端；私有发布消息携带后端及代号，所有权事务条件校验代号。已发布的 RPC／工具结果即使调用方取消，也保持锁保护直至收到归属确认或 Worker 退出。普通资源锁仍会串行化操作并等待上传／下载，因此不承诺恒定耗时或完全无等待的切换。

传输失败保持原位置生效，可重试；中断的单文件以新的不可变上传重新传输，结果不确定的旧对象定位仍保留。切换前取消仅停止复制，切换后返回原位置须重新反向迁移。未取消任务在重启后恢复，并重新验证目标证明。若资源持续产生得比同步更快，完成可能延后，不会强行停止会话或带着缺失原件切换。

无引用资源按具体物理副本判定：不再承担有效归属，且不被进行中操作保护的数据，包括普通孤立原件、取消后的目标副本、切换后的源副本，以及中断或结果不确定的上传。界面保持统一统计及清理入口，不增加按后端细分的垃圾分类。删除前重查生效位置、所有权、迁移及检查保护；持久化删除保护防止迟到消息在回收过程中建立悬空引用，不将远程删除包进 Vista SQL 事务。删除冗余副本不能删除另一后端仍有效的资源身份或会话关联。

上传意图先于正文传输保存；精确 namespace 的对象清单也能发现中断后迟到的 PUT。未完成分片使用 SDK 列举／终止及持久化的精确对象键；即使服务不支持按 namespace 前缀列举分片，也按已登记的精确键恢复，不回退为全 Bucket 扫描或删除其他 namespace。确认删除后才消除恢复记录和占用计数，失败可重试。无法访问的存储报告为无法核实，而不是空存储。统计包括物理副本和原件逻辑大小，不等同于包含加密开销、历史版本的供应商账单。对象存储检查要求 Bucket 未启用版本控制；Vista 不修改 Bucket 策略。

`GET /api/resource-storage` 返回脱敏的 `config.presets`、`activePresetId`、迁移受保护时的 `targetPresetId`、私密分区修订号及迁移状态。`POST` 的 `check`／`save` 接收 `{config, revision, presetId?}`，表单含 `name` 和 DOFS 连接字段。`remove`／`migrate` 要求 `{presetId, revision}`；迁回本地时必须显式发送 `presetId: ""`，省略目标不会选中本地。`activePresetId` 或 `targetPresetId` 为空字符串时表示本地；没有 `targetPresetId` 字段表示没有受保护的迁移目标。选择当前目标不会启动迁移，校验和迁移完成前当前 ID 不变。`cancel`／`retry` 接收 `{migrationId}`。测试或迁移前会验证加密读写及删除；失败通过本次响应的 `checkError` 和最新修订号返回，不启动迁移。`scan`／`clean` 保留异步 202 约定。进度及结果复用按视图订阅的存储 SSE，不使用浏览器轮询。

