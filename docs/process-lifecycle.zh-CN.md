# Worker 与后台任务生命周期

[English](./process-lifecycle.md)

MCP 连接由主进程监督的独立托管进程统一管理，本地 MCP 子进程归属于托管进程的进程会话或 Windows Job，而不归属于某个聊天会话。会话结束释放连接版本的占用；关闭浏览器不影响连接。托管进程退出时清理其本地进程树；意外退出后由主进程退避重启，但不重放已中断的工具调用。`state/mcp-host.json` 保存进程身份，供下次启动或重置清理；`state/mcp-host-data/` 中的临时结果及授权快照随占用释放或恢复清理。托管进程的实测内存计入总预算，并使用与会话进程相同的单进程软上限。

Linux 和 macOS 上每个会话 Worker 是独立进程会话的 leader，Shell 拥有独立进程组并保留 Worker 会话归属，本地 MCP 则归属于托管进程的进程会话。正常退出时 Worker 清理本会话子进程；意外退出时 Server 清理并回收 Worker。Linux 使用 `/proc` 启动时间和 pidfd 核对身份，macOS 使用 `sysctl` 启动时间与会话 ID。Server 保存 Worker 的 PID 和启动身份，下次启动时核对身份并处理遗留进程。macOS 没有 Linux 的父进程死亡信号，Server 退出后由 IPC EOF 触发 Worker 收尾；再次启动也会核对持久化的 Worker 身份。

Windows 使用带 `KILL_ON_JOB_CLOSE` 的 Job Object。启动受管子进程前先为当前进程建立外层 Job，子进程在创建时自动继承；Worker、MCP 托管进程、Shell、本地 MCP 另以挂起状态启动，归入各自 Job 后才继续执行，覆盖父进程在启动中途崩溃的窗口，也避免快速派生子进程逃过归属登记。Job 句柄不传给子进程；所属父进程退出或崩溃时，系统回收该 Job 内的进程树。显式停止同样终止整棵树。持久化身份使用 Windows 进程创建时间，防止 PID 复用误杀。CLI 启动 Server 时同时脱离控制台与允许脱离的终端／SSH Job，服务在启动连接关闭后继续运行；受管 Worker 和工具仍保留在 Vista 的 Job 内。

Windows 可在资源管理器中双击 `vista.exe`，启动或复用已运行的实例，并打开默认浏览器。只隐藏资源管理器启动的启动器控制台，终端命令保留正常输出。启动失败时，原生对话框显示原因及日志路径；浏览器命令无法启动时，对话框提供已运行实例的访问地址。

Windows 的[桌面应用](./desktop.zh-CN.md)负责创建托盘图标，Server 不创建原生窗口。隐藏窗口或退出桌面不会停止 Server。托盘在用户确认后，通过现有本地服务接口发出重启或停止请求。

启动和重启控制进程会显式脱离，因此不依赖被启动或被替换的 Server 继续存活。Server 的外层监管 Job 允许显式脱离；受管子进程各自的 Job 仍禁止脱离，且在恢复执行前完成归入。普通子进程仍在创建时继承外层 Job。隐藏的托盘操作失败时保留原生错误提示，普通终端命令继续使用原有输出。

关闭 Vista 会话会停止 Worker，切换页面或关闭浏览器不会。

## 升级与恢复旧版本

升级前先停止服务，对整个 Vista 配置目录做一份私有的一致备份，包括数据库、配置、凭据、资源和各用户的数据目录。附件存储若配置在此目录之外，也应纳入备份流程。
已有数据仍归默认用户，不搬迁会话数据库，也不更改会话链接。新分支和服务端草稿按用户分别保存。
不要用旧二进制打开已被新版修改的数据。例如，Vista v0.2.4 无法读取新建或重命名用户后写入的 `profiles` 配置。若需回到旧版，停止新版服务，并将升级前的备份恢复到独立目录，不原地覆盖或混合两份数据。备份后的变更不会出现在恢复数据中。

## 端口切换重启

`PUT /api/server-config` 指定与实际套接字不同的端口时，必须在 WebUI 单独确认后携带 `confirmRestart: true`。
隐藏的 `serve-reserved` 新实例先在配置的 IPv4 地址（默认 `0.0.0.0`，或由 `VISTA_HOST` 指定）上绑定新端口，再保存配置；预留与提交使用有界的标准输入／输出控制消息，不传递监听套接字描述符。
预留失败时不保存配置，旧进程继续运行。分区修订冲突会取消准备中的新实例。提交启动失败时，仅通过比较交换恢复本请求写入的分区，绝不覆盖并发编辑。
新实例始终持有目标套接字，最多等待 45 秒让旧实例释放锁，再按正常流程在同一监听器上启动。没有释放后重新绑定目标端口的所有权空档；Linux、macOS、Windows 使用同一机制。
受理响应在旧进程关闭前提供新地址和旧进程身份。受理之后的启动仍可能失败；晚期失败不冒充成功，也不会自动用旧配置覆盖新编辑。
旧标签页保留明确的新标签页入口。直接 HTTP 访问沿用浏览器当前主机名并切换到新端口；HTTPS 反向代理访问保留公开来源，所需的代理上游调整由部署方处理。浏览器不会跳到 Server 的回环控制地址或通配绑定地址。有时限的跨来源图片检查访问 `GET /api/port-ready.svg`，不暴露应用状态，仅确认入口的 HTTP 可用性；它不是常规应用轮询，也不说明上游模型已就绪。未确认结果只允许再次检查地址，不自动重复保存／重启。
服务端数据（含已保存的输入框草稿）保持不变。浏览器偏好和尚未收到保存确认的编辑仍留在原访问来源，不转移身份或登录状态。下述常规同端口重启行为不变。

## Server 进程重启

WebUI 的「重启 Vista」始终要求二次确认，重新启动 Server 进程，不是仅重建 App 运行时、会话 Worker 或刷新浏览器页面。
独立于旧 Server 的控制进程以显式脱离方式启动，复用 CLI 的 `vista restart` 流程：停止 → 等待实例锁释放 → 启动。
它加载当前 Server 可执行文件路径的当前版本，可启用已替换到该路径的新版二进制；不下载或安装更新，也不切换到其他 checkout。
重启沿用当前配置目录和实际监听端口，不额外打开浏览器。
不打开浏览器仅作用于此次重启命令；新 Server 保留原有环境。

会话、资源、凭据、技能、记忆、统计及其他配置均保留，浏览器偏好和草稿也保留。
打开会话的 Worker 按既有准入和健康检查重新创建。旧执行、未完成的子任务及托管后台任务记为中断。符合条件的智能体任务使用持久化会话、模型历史和压缩检查点，在新执行中继续；复用已完成的工具结果，未确认的副作用须先检查再重试。已取消、完成、失败或关闭的任务、待回答的问题和手动压缩不自动继续。托管后台进程不会被保留、重新接管或自动重建。
取消意图先于 Worker IPC 提交，避免取消确认前崩溃使任务复活。关闭服务时暂存持久化重启通知；启动时还会捕获 Server 突然退出遗留的运行中执行，在同一事务中登记中断并激活通知。恢复复用运行时事件准入和 Worker 的 resume 命令，不伪造用户消息。排队用户输入优先，等待准入的恢复通知可跨再次重启保留。通知与对应模型历史一并确认，而不是轮询时确认。仅 Worker 崩溃维持原有中断行为。
模型发现使模型变为可用时，Vista 会重新检查待续跑任务，不用等新消息或其他执行结束。准入和选模规则不变。
外部文件和服务不会回退。

`POST /api/restart` 要求显式 JSON 确认 `{"confirm":"restart"}`。
受理时返回 HTTP 202 及 `{"accepted":true,"instanceId":"<旧 Server 的 instanceId>"}`；该代号属于受理请求的 Server 进程，不表示重启完成。
`GET /api/status` 和共享状态 SSE 的 `instanceId` 在每个 Server 进程生命周期内唯一；同一进程内的全部重置不会改变它。
客户端在确认后只发送一次重启请求，只有共享状态 SSE 已就绪，且收到与重启前 Server 不同的 `instanceId`，才确认成功。
HTTP 202、旧 Server 重新可访问或内部 App／SSE epoch 变化均不足以确认成功。
超时或响应丢失时，结果保持为未确认；自动重连及「重试连接」只恢复共享连接，不会再次发送重启 POST，也不会重放工作。

## 进程内全部重置

确认全部重置后，会在 Server 进程内重启应用运行时。
`internal/server/reset.go` 拦截新的 API 操作，取消旧运行时上下文，等待请求及 `App.background` 工作结束，停止 Worker 并核对遗留进程归属，再关闭 SQLite 并删除用户数据。
所有可能写入运行文件、凭据或持久化状态的异步操作，都必须归入 `App.background`，或由已跟踪的调用者同步等待。
实例锁始终保留。
重新打开空数据后，如果重置后的端口发生变化，`runtimeListener` 会更换监听套接字；旧连接上的重置请求保留到返回新地址。
失败时其他 API 保持不可用，但仍可重试重置或停止服务。

## Shell 与子任务

`shell` 等待前台命令执行结束，默认超时为 60 秒，最长 300 秒。
超时或取消会终止命令及其受管后代进程；命令结束时也会清理残留后代进程。
超时结果明确说明命令已终止，保存的输出来自终止之前。
需要持续运行的窗口程序、服务、监听程序等使用 `start_background`。

Shell 源码写入 `state/shell-scripts/<Worker PID>/` 下的私有临时脚本，避免操作系统命令行长度限制。
Linux／macOS 使用 `/bin/sh`；Windows 使用带 UTF-8 BOM 的 PowerShell 脚本，保留可读错误及原生命令退出码。
前台命令完成、失败或取消后删除脚本；后台脚本保留至任务自然结束或被停止。
Worker 清理时移除对应脚本目录；Server 启动恢复旧进程所有权后清除遗留脚本。
后台状态只携带脱敏、限长的命令预览，此展示限制不截短实际执行的源码。

后台 shell job 默认没有运行期限，由所属会话 Worker 托管。
可选的正数 `timeoutSeconds` 设置自动终止期限；只有设置期限时，工具结果和进程监控才显示到期时间。
现有的后台任务数量和输出容量限制仍然生效。
可选正数 `warnBeforeSeconds` 必须小于 `timeoutSeconds`，且不能单独设置；非法组合不执行。省略表示不预警，每个期限只预警一次，不自动折半、缩放或追加宽限期。`update_background_timeout` 使用 job ID 和准确的 `expectedExpiresAt` 比较交换期限；此前不限时则传空字符串。新 `timeoutSeconds` 从本次调整请求起计算，省略新的预警参数会关闭预警。失败或过期决定不延期，原硬计时器在持久确认前保持有效；退出或停止后不能调整。`read_tool_output(jobId)` 同时提供当前状态与期限元数据，便于冲突后检查。预警和期限调整使用标准计时器，硬终止不等待模型或事件投递。
每会话活动 job 数量由容量设置控制（默认 4），占位包含启动和收尾；降低不杀现有进程。退出、停止和超时清理后释放名额；已捕获输出保留，外部副作用不回退。

后台 shell job 和 `detached` 子任务都归属 Vista 会话，可以跨过一次前台执行的结束或取消。`required` 子任务阻塞父任务提交，`best_effort` 在父任务收尾时取消。显式停止子任务会取消其现有后代，包括 detached 后代；正常父任务收尾保留 detached 工作。

子任务启动先持久化并 ACK，再返回任务 ID 和执行模型调用；终态与报告也在确认落盘后才供父任务收集。后台任务及其后代在父执行结束后仍可向原执行过程写入模型正文、工具记录和报告；它们不生成新的正式 assistant 消息。状态保存在 `agent_tasks`，报告正文复用事件与模型输出分块。Worker 退出、会话关闭或 Vista 重启会把未完成任务记录为中断，不自动恢复副作用。

工具执行先持久化并 ACK 工具开始事件。未能确认结果的工具记录为 unknown；正在运行的后台子任务不使已经完成的前台执行变成失败。显式停止某个子任务不改变已提交的前台答复。

前台 shell 和大工具输出保存为 artifact；后台 shell 保存为 job。中断后保留已保存字节，并明确输出是否完整。Unix 进程清理覆盖仍属于 Worker 进程会话／工具进程组的后代，无法保证清理主动 `setsid` 脱离会话的外部程序。Windows Job 覆盖正常派生的后代；通过系统服务等外部机制创建的进程不在此保证范围内。

仓库根目录执行 `make test integration` 会覆盖普通 Worker 崩溃、Server 崩溃及 Server/Worker 双崩溃，包含在 `make test all` 中。底层 Linux 集成入口为 `scripts/worker_crash_smoke.mjs` 和 `scripts/background_job_smoke.mjs`；前者可设置 `VISTA_CRASH_MASTER=1`，后者可设置 `VISTA_DOUBLE_CRASH=1`。直接运行脚本时使用独立测试状态和 `VISTA_BIN` 指定待测产物。

跨平台底层测试位于 `internal/platform/platform_test.go`，Windows 另验证父进程突然退出会关闭受管 Job，而显式脱离的控制进程仍能存活。`cmd/vista/platform_test.go` 的 `TestNativeApplication` 通过真实应用产物检验启停、配置、Worker、Shell、取消、后台任务与崩溃恢复；`TestNativeResetPort` 验证重置、端口切换、实例发现和端口冲突后的重试；`TestNativeWindowsDesktopLauncher` 使用独立的父进程和浏览器替身，验证资源管理器启动路径、实例复用及原生启动错误对话框。[原生 Wails 托盘测试](./testing.zh-CN.md)覆盖单一图标、重新打开同一窗口、状态、重启和停止。
