## 进程与存储归属

打开的会话通常拥有常驻 Worker，受准入与故障恢复约束。主线程顺序执行，工具、子任务及不同会话可并行。会话没有固定工作目录，文件和 shell 工具接收明确路径。

Server 负责 SQLite 写入和会话内事件序号。Worker 通过本地管道发送结果，工具启动、子任务启动／终态及检查点等边界等待持久化确认。浏览器接收已持久化事件，按序号去重 SSE 重放。模型正文分块保存，工具和进程产物按需读取。见[进程生命周期](./process-lifecycle.zh-CN.md)。

[目录解析](../internal/appdirs/dirs.go)使用 `os.UserConfigDir()/vista`。`models.json`、`mcp.json`、`search.json`、`user-agent.json`、全局 `AGENTS.md`、`skills/`、`omp-models.json`、`model-catalog-status.json` 等配置与凭据位于该根目录。SQLite、实例记录、锁、日志、输出及资源原件位于 `state/`。模型目录文件不在 `state/` 内。

`GET /api/status` 提供版本、缓存的可执行文件 SHA-256、Go 源码提交及 dirty 状态、服务所在系统及版本。`internal/buildinfo.Version` 默认为 `dev`，Makefile 可指定发布版本。不注入构建时间，二进制哈希在启动时计算，不回写可执行文件。

## 会话同步

`GET /api/sessions/<id>/snapshot` 在同一个 SQLite 事务中读取会话核心视图及其 `throughSequence` 边界。
内容包括当前执行／待交互状态、最新正式答复序号、有界的近期消息／事件、消息调用统计及最新撤回序号。
近期事件页之外的主线程进度会额外带入，分页边界仍指向原事件页。
完整输出、执行索引、反馈及上下文估算独立加载，不阻塞 SSE 订阅。

SSE 的 `record` 帧携带 `afterSequence`，表示前一条已发送边界，无需假设撤回后的存储序号连续即可检测漏传。
独立的 `sync` 帧在初始补齐、每 15 秒及执行结束／撤回后报告持久化状态。
校验点之前先发送其边界内的事件；校验点本身不推进浏览器的已应用游标。

当前会话由 `web/src/client/conversationSync.ts` 统一管理初始化和串行恢复。
流失败、45 秒未收到字节、接续边界／校验点不符、回到前台／恢复联网或手动重试时，按需校正视图。
恢复最多补读十页事件，可通过包含上界的 `through` 参数固定目标；补读无法恢复时重建核心快照。
建立连接和恢复读取各有 10 秒超时；重连从一秒退避到最多 30 秒，遇到不可恢复的客户端错误或已关闭会话时停止。
重新打开当前会话时恢复订阅，保留输入区状态。
会话恢复不会提交模型或工具请求，也不会定时轮询会话内容。

替换视图保留草稿、引用、附件、选模、主动查看的历史窗口及快照之后已确认接收的消息。
只有基于可见性的已读机制确认答复已读。
同步错误拥有独立重试入口，并在执行调试框中保留有界诊断；发送成功不会清除同步错误。
执行详情的渲染错误被隔离，Markdown 失败时显示转义后的纯文本，保留正式答复。

## 工作区同步

每个页面除当前会话的持久事件流外，共用一条通过 fetch 建立的 `GET /api/events` 状态流。
初始检查点提供连接级 `subscriptionId`；合并的 `PUT /api/events/subscriptions` 更新关注主题及查看者时区，无需重新建立状态流。
关闭视图释放相应关注，断开连接释放整份订阅；可选快照仅为关注该主题的客户端读取和推送。
技能及选模统计仅传递修订号；可见视图通过 HTTP 读取带版本的列表，并复用版本匹配的缓存。
跨平台文件监听仅覆盖受管技能／资源根目录及直接子目录，包括原子替换；不跟随符号链接，也不监听任意工作目录。
资源及引用提交使存储统计代次失效；合并后的单次扫描服务所有关注存储的视图，扫描期间出现新变化会安排补扫。
最后一个存储视图关闭时取消自动扫描；显式清理独立继续执行。
可见的选模统计也接收整点通知以更新滚动观测窗口，重新打开时最多复用一小时缓存。
资源清理仍须显式确认；发现文件或引用变化不会自动删除资源。
`internal/server/state_events.go` 在修改提交及异步状态转换后，合并发送各主题的修订号。
变化后的会话列表、运行状态、模型列表、目录更新状态／历史、资源扫描状态、MCP 设置／登录结果、服务商登录结果及记忆数量／容量限制，以有界数据随同一帧发送。
工作区读取 `GET /api/sessions?open=true`；全局会话载荷同样只含打开的会话摘要和对应事件边界。
已关闭会话只在运行状态中提供汇总数量，不携带其摘要或聊天记录。
管理会话页仅在挂载期间订阅会话修订号，进入页面及数据变化时读取 `GET /api/sessions?page=1&pageSize=10`；可选的 `search` 和 `open` 筛选在全部会话范围内先执行，再计算总数及分页。
当前页以一份快照整体替换，避免混用不同时间点的打开、关闭列表，使并发关闭／重开操作造成会话短暂消失；退出时取消未完成读取并释放订阅，不重连共用状态流。
两处管理列表均默认每页 10 条，可切换为 20／50／100 条，并且只读取当前页；总数及当前页在同一 SQLite 事务中读取，删除导致页码超出范围时自动退回有效页。
记忆管理仅在二级弹框打开时读取 `GET /api/memories?page=1&pageSize=10`；全局记忆事件只携带数量和容量限制，不包含正文。
分页响应包含读取前取得的服务端代次／修订号 `version`；版本匹配时复用当前页（包括记忆修改返回的页面），修订号变化时只为打开的视图读取该页。
当前会话从打开列表消失时，通过 `GET /api/sessions/<id>/checkpoint` 区分关闭和删除，不读取全部已关闭会话或聊天记录；当前已关闭会话仍可阅读，并保留草稿。
未分页的会话和记忆接口保留既有响应结构，供管理客户端使用；未分页会话列表最多返回 1,000 条摘要。
登录结果按登录 ID 匹配；设备码和授权链接继续通过对应登录的 HTTP 请求读取。
新打开的视图复用对应修订号的最新数据；各订阅的独立游标将首次读取与后续更新串行处理，避免重复初始化。
记忆更新保留未保存的编辑，以及检测编辑／删除冲突所用的原始文本；另一客户端删除正在编辑的条目时，也不会丢失草稿。
已读回执、标题、模型选择和排队消息编辑只推送会话列表，不重复发送运行状态。
执行／压缩、子任务／进程和 Worker 生命周期变化同时推送运行状态；模型和工具进展继续走会话事件流。
消息发送和执行控制成功后不再单独刷新工作区，由状态流同步共享视图。
会话列表与各会话的事件序号边界在同一个 SQLite 读取事务中生成；应用迟到的列表时，优先保留较新的会话事件和已确认接收的消息。
全局修订号在读取快照之前取得，保证并发提交仍会产生后续通知。
连接建立时及每 15 秒的心跳都会携带服务端代次和完整修订号；`web/src/client/workspaceSync.ts` 直接应用变化后的数据，仅在变化的主题缺少数据时重新读取对应快照。
初次连接和重连使用 HTTP 快照校准；修订号未变化的心跳不重复发送数据，也不触发 HTTP 查询。
帧的 JSON 超过 120,000 字节时，依次省略最大的载荷直到符合上限，保留各主题修订号以通过 HTTP 定向恢复，避免超过共用 SSE 传输的帧上限。
重连或服务端代次变化时重新核对全部已订阅视图，页面恢复前台或网络连接时重新建立状态流。
读取失败不会确认该检查点，而是通过连接恢复重试；修订号未变化的心跳不触发 HTTP 查询。
两类事件流共用 `sse.ts` 中的连接超时、空闲超时、取消和重连退避机制。

初始／恢复快照、过大的列表、服务商配置目录、诊断正文、历史、文件和有界输出分页继续按需通过普通 HTTP 读取，操作提交继续通过普通 HTTP 写入。
服务商连接修改依赖状态通知，不再刷新无关的工作区快照；连接设置与服务商配置目录分别读取。
前端不再定时查询工作区信息、目录更新进度、登录状态、资源扫描、进程详情和日志增长。
开启调试订阅后，后端每 5 秒通过同一条流发送指标；页面隐藏或关闭调试模式时停止请求采样。
后台进程写入输出时，通过持久任务事件限频报告字节数；输出视图按需更新有界的可见块和尾部块，并保留虚拟滚动缓存。
后端的目录更新调度、模型发现和上游设备授权轮询继续遵循各自的生命周期。

## 活跃与消耗统计

`internal/store/statistics.go` 管理 UTC 分钟级活跃表和按请求去重的词元账本，不关联会话外键；撤回或删除会话不会退回已产生的消耗。
`provider.WithUsageRecorder` 在统一模型调度入口观察 API 调用，覆盖主／子请求、压缩、文字／图片标题生成，以及有上报部分用量的失败调用。
Worker 发送有界 `token_usage` 帧，Server 校验身份并提交去重记录后才递增 `statistics` 修订号；主进程的标题请求直接写入同一存储。
仅保存输入与输出的合计，缓存读取和推理词元不再次相加；缺失用量保存为空值，不以估算值或零补齐。
失败或取消且没有有效用量的请求不写入账本；流中断时保留已收到的有效用量，但不把未完成输出视为成功结果。
初始化仅补入一次仍保留的 `model_result` 用量并记录覆盖起点，正常重启不重复导入新调度记录。
保留时间与最长可查看周期一致，为 90 天；初始化以及活跃或用量写入时，统一清理两张表中的过期记录。
前端将可见页面内的可信输入事件合并为有界 `POST /api/activity` 分钟报告，15 秒后或页面退出／隐藏时提交；闲置页面不产生报告，多客户端重叠操作按 UTC 分钟去重。
报告不含按键值、消息正文或导航路径，最多接受 120 个近期分钟。
`GET /api/statistics?days=30&timezone=Asia%2FHong_Kong` 在同一 SQLite 读取事务内返回 7／30／90 天内的每日序列、星期／小时活跃、总量及覆盖范围；内嵌 IANA 时区数据保证跨平台运行。
`hours` 矩阵为已观测本地日期／小时的平均活跃分钟；分母包含未活跃时段，排除开始记录前及尚未到来的小时，夏令时重复小时按同一本地日期／小时计一次，不存在的小时不计入。
全局流只携带统计修订号，图表历史仅在统计页挂载时读取，复用带版本的缓存并保留取消、迟到响应拒绝及重连恢复，不轮询或向无关客户端广播图表历史。
`POST /api/statistics/reset` 要求 `{"confirm":"reset-statistics"}`，在同一事务中清空两张统计表、更新覆盖起点并保留一次性导入标记，提交后才发布统计修订号。
忽略重置所在分钟及之前的活跃上报，防止客户端迟到缓冲恢复已清空的活跃记录；重置后完成的请求用量计入新账本。
统计视图订阅期间，连接按查看者时区的下一整点触发修订号变化，覆盖午夜及夏令时切换；关闭视图停止该时间通知。
关闭期间跨越整点后重新打开，即使没有新写入，也会使本地图表缓存失效。

## 执行与子任务

执行中的普通发送在下一决策边界插话，明确排队的消息等待执行结束。取消／失败暂停未投递输入；停止后新发消息独立开始，不释放旧暂停队列。选模变化从后续执行生效。

[委派注册表](../internal/agent/delegation.go)通过稳定任务 ID 关联父任务及原执行：

| 策略 | 最终提交行为 |
| --- | --- |
| `required` | 等待终态，收集持久化报告；仍有未收集报告时让模型综合。 |
| `best_effort` | 不阻塞提交；父任务收尾时取消未完成工作。 |
| `detached` | 归会话所有，可超过父执行及其取消的生命周期；报告留在原过程，不新增正式答复。 |

明确取消子任务也会取消其后代。同一父智能体的后续执行可查询或取消其 detached 任务。关闭会话或停止 Vista 会结束受管工作。

模型提出不含工具的候选答案后，运行循环在结束前检查尚未收集的 required 子任务。收集结果作为结构化运行时证据（`RuntimeData`），共享 16 KiB 内联预览，保留补读引用；语义综合仍由模型完成。同一执行可在插话边界保留多条正式答复，不是整个生命周期只允许一条消息。

共享的 `runScope.modelTurns` 用于分配轮次编号，不是模型调用预算。运行时校验委派深度，但没有统一的整轮 deadline、累计调用预算或有上限的 join 代次计数。

检查清单是按执行归属的替换事件，不是会话全局状态；新执行不继承旧清单。工具按自身参数规则校验，参数错误作为该次工具结果返回。有效 `question` 仅主智能体可调用，且必须是该模型轮次唯一工具；问题保留到回答或被替代。服务商已执行的托管工具只保存，不再作为本地工具调度。

## 上下文接续

主模型消息及工具结果存入不可变历史文件，通过确认后的 `model_history` 引用提交。后续执行按事件顺序与正式输入合并，排除重复的正式 assistant 投影。中断后缺少的工具结果恢复为明确的未知状态，不执行工具。

自动压缩要求上游明确的上下文超限证据；手动压缩在空闲时共用摘要／检查点存储。模型目录窗口和保留词元估算不触发压缩。检查点通过事件与输入截止位置替代旧历史，保留工具配对、资源引用和协议回放字段；摘要失败不替换当前检查点。见[上下文压缩](./context-compaction.zh-CN.md)。

全局提示词、偏好、当前清单及可用工具信息按执行重新组装，项目规则和技能正文按需读取。切换模型／协议时去除不兼容的服务商回放数据，保留可移植正文、工具配对及资源引用。

主智能体通过 `memory` 的 `list`、`add`、`update`、`remove` 管理明确的长期偏好。`update` 接受单条编辑字段，或由现有记忆的 `update`／`remove` 操作组成的 `changes` 数组；每个 ID 只能出现一次，并须提供从 `list` 取得的准确 `previousText`。Server 校验所有目标、最终文本唯一性和最终容量后，在同一事务中提交全部变更及一条 `memory_changed` 审计事件。保留条目的 ID 和创建时间不变；冲突或写入失败时整组保持原状。提交后才向 Worker 确认成功，并发布一次共用状态通知。`list` 同时返回既有上限：128 条、每条 4,096 个 UTF-8 字节、合计 32 KiB。编码后的变更须为 64 KiB 的 Worker 帧预留 4 KiB 元信息空间；过大请求返回可恢复的工具错误。归并仍由当前主智能体判断，不增加独立的记忆分析请求或后台整理任务。

回复语言作为请求元信息，由子任务继承，插话携带新偏好时更新。公共模型请求入口在协议转换前，将 `internal/replylanguage` 中的统一规则应用到请求副本；正文、标题和压缩提示词不再各自定义语言规则。用户明确指定的语言优先于默认值，没有有效偏好时默认跟随用户消息。词元估算使用同一组装路径，生成的语言指令不保存到模型历史或检查点。

## 模型请求恢复

`internal/provider/model_retry.go` 为所有协议适配器统一管理重试预算；Bedrock 关闭 SDK 自带重试，避免叠加次数。
符合条件的模型请求在首次尝试之外最多重试三次，默认等待 2／4／8 秒，并加入 ±20% 抖动。
适用范围为 HTTP 408／429／500／502／503／504／529 以及收到响应前的网络故障；已知认证、计费／额度、模型下线和上下文超限错误除外。
有效的 `Retry-After-Ms` 或 `Retry-After` 是最短等待时间；要求等待超过一分钟时结束恢复，不缩短上游要求的等待。
等待和请求均响应取消。
恢复沿用组装好的消息、工具及模型选择，不重新执行本地工具，也不改选模型。
流或协议错误，以及已经输出正文／推理或返回工具调用、上游已执行调用、用量的尝试，不自动重放。
上下文超限压缩仍使用独立机制。

每次 HTTP 尝试分别记录调试信息和用量；未上报用量的失败尝试不增加消耗。
会话恢复先持久化有界的 `model_retry` 事件，再通知持久化会话流；每次额外尝试使用同一个逻辑轮次 ID 记录 `model_request`。
即使子任务活动超过近期事件页，快照仍保留主智能体的重试进度。
界面将同一轮次的重试合为一个恢复步骤，并在刷新或重连后恢复等待状态。

打开且空闲的会话，其最近一次执行失败后可点击“继续执行”，通过既有消息接口发送一条本地化的继续任务消息，使用当前所选模型。
操作保留工具历史、未发送的草稿、引用和附件，不撤回原消息，也不自动重新提交原始完整请求。
继续任务的消息要求模型沿用已有结果，并在重复结果不确定的操作前先核实状态。

## 模型 HTTP 调试

调试模式通过发送消息的浏览器所携带的 `vista-debug-mode` Cookie，为新执行启用模型 HTTP 记录。
排队消息保留该选择，子任务继承它；标题和压缩请求分别标明用途。
`internal/modeltrace` 在凭据刷新、认证或签名之后观察模型推理请求，不记录登录和令牌交换。
记录包含请求 URL、请求头、已读取的请求体、HTTP 状态、响应头、已读取的原始响应、接收时间、完成或错误状态，以及可提供的解析计数。
Chat 调试还记录当前 SSE 行号和事件序号、实际出现的推理字段、片段数、合并后的块数及保留字节数。
Chat 适配器先合并兼容的推理片段，再检查 64 KiB 和 256 个独立块的保留上限；不透明块和签名不兼容的块分别保留。

请求完成或失败后，记录在认证信息脱敏后写入 `state/model-diagnostics/<session>/<run>/`。
记录包含提示词和响应正文，独立于模型历史，不会再发送给模型。
每次模型调用最多记录 1 MiB 请求体、2 MiB 响应体、8 次 HTTP 交互，每次交互最多保留 2,048 条接收时间；达到上限会明确标明截断，不会截断实际请求或响应。
二进制响应体使用 base64，时间记录中的偏移量对应脱敏前的原始字节。
最多保留 256 条记录，总量不超过 128 MiB；启动时、每小时和写入时清理超过 7 天的记录。
删除会话或重置 Vista 会移除对应调试记录。

`GET /api/sessions/<session>/runs/<run>/diagnostics` 列出已保存的调用摘要，追加 `/<record>` 读取单条记录。
两个接口均检查执行所属会话并禁止缓存。
执行过程中的调试弹框独立于会话 SSE 读取记录，提供请求选择、原始响应展示和复制。
文件原子保存成功后，Worker 上报记录 ID；Server 核实其简短摘要后，通过共享状态流发布索引更新。
标题请求使用同一通知路径，压缩／子任务请求保留所属执行信息。
传输缓存最多保留 256 条近期摘要；修订号覆盖范围用于检测遗漏，并回退到该次执行的 HTTP 索引。
只有打开的模型 HTTP 页签订阅更新；其它执行的记录不会触发索引／正文读取，新增记录也不会打断当前选中的不可变正文。
此前未采集的请求，以及因进程终止而中断的请求，无法事后还原。

## 服务商与工具

OMP 和 models.dev 提供模型资料，Vista 负责路由与认证，自定义连接明确指定 API 格式。两个目录来源整体暂存、安装，失败保留旧目录。已有执行使用自己的配置快照。见[服务商路由](./providers.zh-CN.md)。

`websearch` 按保存顺序尝试外部服务；`webfetch` 按独立保存的顺序尝试 Jina Reader／DeepSeek，默认 Jina 优先。首次搜索顺序只随机一次；各读取器完整解码并暂存后才可选为成功结果，正文为空、明确的错误／验证页、仅提示启用 JS 或返回格式不受支持时，继续尝试下一已配置读取器，正常短内容可成功。没有内置原站抓取／转换器；本地或私有内容通过 `shell` 下载。DeepSeek 搜索和读取密钥分别配置。首次输出默认一次搜索全部结果合计 50 KiB、每页正文 50 KiB，按 UTF-8 字节计算，0 取消首次截短。搜索来源信息和摘要共用一份结果预算，产物／补读元数据另计。旧字符配置的默认值升级为新默认值，不限制保持不变，自定义值按 UTF-8 最大容量换算并向上取整为 KiB。网络结果没有第二层固定工具结果截断，显式补读仍按字节分页。配置保存在 `search.json`，从下一次执行生效。

文件搜索在进入被忽略目录前应用祖先和嵌套 `.gitignore` 及例外规则；明确读取不受此限制。`read_file` 使用从 1 开始的 `startLine`、`lineCount`（默认 200），返回原行号及 `nextLine`，流式扫描完整原文件以计算哈希和总行数，选中行暂存到磁盘。过大的单行流式保存为产物，不整行载入内存。搜索覆盖超过 1 MiB 的文件，保持全局 32 MiB／10,000 文件／100 结果预算，并显式标明结果不完整；`read_tool_output` 仍按字节读取。

原生工具参数共用 `internal/toolinput` 声明的 256 KiB 完整 JSON 预算，服务商适配器与运行时校验复用同一常量。
`delegate.task` 使用 8 KiB 提示词预算；工具声明明确按 UTF-8 字节计算，并建议将更长的支持材料放入文件后引用。
`shell` 与 `start_background` 不再单独限制命令为 4 KiB，工具声明提示完整 JSON 预算。
运行时参数长度错误在工具副作用发生前返回 `executed: false`、字段名、实际与最大字节数及恢复建议。

`write_file` 在锁内校验 SHA-256 的同一次读取中保留有限原文，原子替换成功后生成统一差异。
差异作为不可变会话产物保存；模型上下文及事件预览携带引用，不重复携带变更正文。
界面区分新建、覆盖、空文件及内容未变；原文件超过 1 MiB 时省略差异，但不阻止合法替换。
保存这份展示资料失败，不会把已经提交的写入改判为工具失败。
Shell 与 MCP 的文件副作用不自动生成差异，Vista 不对其工作目录做快照。

执行 `read_file`、`write_file`、`search`、文件路径形式的 `read_skill`／`read_resource`、`shell` 或 `start_background` 前，工具运行时按明确的目标路径或工作目录，从外到内发现祖先目录中的 `AGENTS.md`、`CLAUDE.md` 和 `.github/copilot-instructions.md`。
没有规则，或模型保留上下文中已完整读取所有适用规则的当前版本时，直接执行原操作，省去单独发现规则的模型轮次。
否则返回 `instructions_required`、`executed: false` 及未读文件的路径、大小和 SHA-256，原操作不产生副作用。
模型通过 `read_project_instruction` 读完全部分页，按作用范围和优先级应用，再重试或调整操作。
每次成功请求按工具配对结果重建已读范围，各任务独立，因此同轮读取不会提前放行并发操作；缺失分页、文件变更和压缩后不再保留的正文均须重读。
检查不缓存空目录，也不解析 shell 命令中的其它目标路径；跨目录工作仍可显式使用 `project_instructions`。
内置 `skill://` 文档和按哈希读取的资源没有需要检查的文件系统目标。

MCP 设置保存为 `mcp.json`，稳定 ID 与显示名称分离。独立且受监督的 MCP 托管进程统一拥有本地 stdio 服务和远程连接，包括使用 MCP 的网络搜索。启动后以有限并发异步预连接，跨执行复用。每次执行及其分离子任务保留所用配置版本；编辑、禁用或删除影响后续执行，旧版本无人使用时关闭；改名保留连接。设置中的连接检查复用同一托管入口。会话进程直接与私有托管端点交换工具数据，大结果通过临时文件传递，不经过主进程。断线后退避重连，不自动重放副作用不确定的中断调用。服务自身的浏览器、工作区等状态可能跨会话共享。OAuth 仅在授权、握手成功且连接配置未变时发布凭据。界面和状态入口见[前端](../web/README.zh-CN.md)。

MCP OAuth 使用 SDK 的授权码与 PKCE 流程，不启动回调监听器（`internal/mcpclient/oauth.go`）。
重定向 URI 固定为 `http://127.0.0.1:5186/callback`，独立于 Vista 的监听端口，只用于标识授权响应，不要求浏览器成功打开。
授权服务器须接受该重定向 URI，并通过查询参数返回结果。
用户打开授权链接后，将最终地址完整粘贴回 Vista；即使浏览器提示无法连接回调页面，也可提交地址栏中的链接。
`POST /api/mcp-auth/<id>` 接受有大小上限的 JSON 请求体 `{"callbackUrl":"<完整回调 URL>"}`；URL 最多 8192 字节，只解析、不请求，并在交换凭据前校验本次授权的回调地址与 state。
格式错误、重复参数、地址或 state 不匹配返回 400，不消耗等待中的授权；有效的 OAuth 拒绝响应会结束本次授权，不交换授权码。
接受提交后返回 `exchanging` 状态并移除授权链接；非 `pending`、重复提交或已结束的授权返回 409。
保留 SDK 的签发方与 PKCE 校验；五分钟有效期覆盖授权及连接建立，取消或连接配置变更均阻止迟到凭据发布。
`GET` 读取单次授权，`DELETE` 可取消授权，包括正在交换凭据的阶段。
授权链接仅通过单次授权读取；粘贴的响应不回显、不进入共享状态，共享登录更新仅含 ID、状态及脱敏错误信息。

系统技能从 [`internal/tools/systemskills/`](../internal/tools/systemskills/) 的内置文件夹发现。每个文件夹只提供英文 `SKILL.md` 及配套文档，新增文件夹无需逐技能修改注册表或界面。`system:<文件夹>` 标识与 `skill://system/<文件夹>/` 读取路径独立于用户文件夹；`read_skill` 直接读取内置 Markdown，不释放文件。设置界面和运行时使用同一份英文元数据与文档，不随界面语言切换。用户技能仍位于配置根目录的普通文件夹中。

`POST /api/extension-import` 接受 `source: "opencode"`、`kind: "mcp" | "skills"`、`action: "preview" | "import"`、可选 `configPath` 和来源工作目录 `directory`（绝对路径，默认 Vista 启动目录）。确认时需要返回的 `fingerprint` 及选中的 `ids`，并重新读取来源配置及解析后的引用；技能指纹还包含每个文件的内容和可执行权限。来源改变后须重新预览。预览不返回凭据、不保存配置；导入保留已有目标，不修改来源文件。

MCP 导入同时接受 v2 的 `mcp.servers` 和 v1 的平铺服务条目，同一文档内优先使用原生条目；保留禁用状态，解析本地命令和目录，转移兼容的 Bearer 令牌、自定义 HTTP 请求头或 OAuth 客户端设置。设置读取不返回请求头的值，可在高级设置中保留、替换或删除。不支持的环境变量、超时及传输选项会跳过，不会静默丢弃。OAuth 服务可能需要在 Vista 重新授权。技能导入扫描全局 `skill/`、`skills/` 和 `skills` 中配置的路径（v2 数组或 v1 的 `paths`／`urls` 对象），先暂存完整副本，再独占创建新目标，失败时清理本次新建目录。远程技能 URL 及不支持的文件／链接结构不会导入。两类导入均不执行来源插件；配置保存后，由托管进程异步连接已启用的 MCP 服务。

## 资源、回退与限制

原始附件位于 `state/resources/<哈希前缀>/<SHA-256>`，SQLite 只存元数据和归属，不存图片字节。Server 流式接收原始上传，Worker 校验最多 50 MiB 的原件、发布并等待会话归属提交确认。图片字节及含图片的模型请求均留在 Worker。新附件及显式 `read_resource(path|hash)` 结果只激活下一次请求的视觉输入，规范历史和检查点保留引用。见[资源约定](./resources.zh-CN.md)。

撤回或编辑提交先停止该会话工作，再从所选用户消息处截断历史，不撤销文件或其他工具副作用，也不复用事件序号。见[消息回退](./message-revert.zh-CN.md)。

关于 Vista 通过 `capacity.json` 及 `GET`／`PUT /api/memory-config` 提供内存预设和自定义限制，共用状态 SSE 携带已保存配置及主进程／Worker／MCP 托管进程的实际 RSS。默认总准入预算 2,048 MiB、单 Worker 或 MCP 托管进程 1,024 MiB、同时执行四个会话（包含后台活动），不设固定打开会话数上限。[准入实现](../internal/server/admission.go)在实测占用达到预算或系统可用内存低于 128 MiB 时拒绝新 Worker、执行和图片操作。限制变更发送到现有 Worker 和 MCP 托管进程；Go 软内存目标分别为各自限制的 75% 和 90%，每秒 RSS 检查停止超过限制的进程。这是软保护，并非操作系统硬上限或峰值估算；采样间隔内仍可能出现瞬时峰值，外部 shell/MCP 子进程内存不计入准入总量。中断工作记录状态，不自动重放。组件缓冲限制和单次操作超时不等于通用任务容量保证，见[验证](./testing.zh-CN.md)。

服务监听回环地址，校验 Host/Origin，工具以本机用户权限执行，无逐次调用审批。HTTP／流错误保留脱敏后的服务商诊断，在消息区展示；实际步骤错误保留在步骤内。平台层实现 Linux、Windows 和 macOS 进程管理。
