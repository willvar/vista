# Settings contracts

Read existing settings before changing them. Send JSON bodies with `Content-Type: application/json`; HTTP errors must be surfaced before claiming success. Responses redact saved credentials; blank fields usually preserve secrets on edits. Do not copy redacted GET responses into PUT requests blindly.

## Model connections

- `GET /api/model-config` lists saved connection anchors. `GET /api/provider-config` lists built-in setup choices and their supported fields. `GET /api/models` lists currently usable models.
- `POST /api/provider-config` creates a connection; `PUT` edits one using its anchor `key`; `DELETE` removes that connection with `{"key":"..."}`. Read the current setup list before forming the request.
- Custom connection fields: `name`, `providerId: "custom"`, `provider` (one of `openai-chat`, `openai-responses`, `anthropic`, `gemini`, `cohere`), `baseUrl`, `credentialMode` (`none`, `bearer`, `x-api-key`, `x-goog-api-key`), optional `apiKey`, and `headers`. Authentication and API format are independent. Vista discovers models; provide `ids` only if discovery is unavailable and the user has a known model ID. A failure returns a `code`, `message`, and optional `details`.
- Built-in connections use `provider: "catalog"`, their `providerId`, and the fields/modes from `/api/provider-config`. Do not convert OAuth credentials to API keys. Use the WebUI login flow when credentials cannot be transferred.
- `POST /api/provider-import` accepts `source: "opencode"`, `action: "preview"` or `"import"`, optional absolute `configPath` and `credentialPath`. Confirmation also requires the preview `fingerprint` and selected `ids`. Declarative OpenCode v1/v2 configuration and portable credentials are recognized automatically. Preview reads `auth.json` and the read-only v2 credential database; an explicit `credentialPath` reads only that file. Different credentials for one connection have `credentialGroup` / `credentialSource`; choose at most one entry per group. Plugins are reported without execution. Existing connections are kept; one failed selected connection prevents the entire batch from saving. Deselect a failed connection or repair its source credentials before retrying.

## MCP and skills

- `GET /api/mcp-config` returns servers, `maxServers`, and `defaultDirectory`. `POST` adds and `PUT` edits a server; edits include its stable `id`. `PATCH` sets `disabled`; `DELETE` removes by `id`.
- MCP fields: `name`, `transport` (`stdio` or `http`). Local servers need absolute `command`, `directory`, and `args` as an array. HTTP servers need `endpoint`, optionally `token`, custom `headers`, or `oauth: true` with `clientId`/`clientSecret`. GET exposes saved `headerNames`, not values; omit `headers` to preserve them, use blank values for existing names to reuse them, or send `{}` to remove all. Custom `Authorization` cannot be combined with token/OAuth authentication. Non-loopback HTTP is unsupported. Saving starts enabled services asynchronously, including local commands; disabled services stay stopped. Connection checks inspect tools through the shared host; OAuth login remains an explicit WebUI action. An active execution keeps its original MCP configuration.
- `GET /api/skills` returns system and user skills and the user `directory`. System skill IDs start with `system:`; they are embedded, immutable, and read with `read_skill` using `skill://system/...`. User skills live in folders containing `SKILL.md` plus optional supporting files under the returned directory. Use complete folders rather than copying only the entrypoint.
- `GET /api/skills/<id>` reads a skill. User-only mutations: `PUT {content, sha256}` updates `SKILL.md`, `PATCH {disabled}` toggles availability, and `DELETE` removes the entire folder. Re-read before editing if the digest changed. Refresh discovers files directly; no database registration is required.
- `POST /api/extension-import` imports OpenCode v1/v2 MCP services or skill folders: `source: "opencode"`, `kind: "mcp"` or `"skills"`, `action: "preview"` or `"import"`, optional `configPath` and absolute source `directory`. Confirmation requires the preview `fingerprint` and selected `ids`. Preview entries include skip reasons; preserve incompatible settings rather than silently discarding them. Existing destinations are never overwritten. Skills are copied as complete folders including assets and scripts. Enabled MCP services are connected asynchronously after import; disabled entries remain stopped. Changed sources require rereading, and OAuth services may require authorization in Vista.

## Personalization

- `GET /api/agent-settings` reads global instructions, delegation limits and `automaticTitles` (enabled by default); `PUT` updates only the supplied fields. Disabling automatic titles skips the extra title model request and keeps the default name, displayed by the UI as a localized “New Session” prefix plus its creation timestamp (`YYYYMMDDHHmmss`, client local time); existing and manual titles stay unchanged. Global instructions are the configuration-root `AGENTS.md`. Filesystem tools automatically check their target path, and shell tools check their working directory for scoped rules. With no unread rules they run immediately; `instructions_required` means the operation has not run. Read all rule pages before retrying or revising it. Use `project_instructions` for other paths, including shell targets outside the working directory. Nearer rules take precedence in their scope; explicit current requests take precedence over defaults.
- `GET /api/memories` lists saved preferences. The main agent's `memory` tool updates explicit lasting preferences. Child agents inherit preferences but cannot call `memory`. Do not turn a one-off request into permanent memory.
- Settings persist for future runs. Explain whether a connection was merely saved, its model list was fetched, or a real model/MCP request was verified.

## Network queries, resources and memory

- `GET /api/search-config` reads search/page-reader order, credential presence and initial UTF-8 byte budgets; `PATCH` updates only supplied fields. `searchPreviewBytes` budgets the combined search payload (sources and summaries); `fetchPreviewBytes` budgets page text. Each defaults to 51200 bytes (50 KiB); continuation metadata is additional. Page readers are `jina` and `deepseek`, defaulting to Jina first. `PUT {name, apiKey}` saves a key; `DELETE {name}` removes it. DeepSeek search uses `name: "deepseek"`; its separate page-reading key uses `name: "deepseek-fetch"`. Zero disables initial truncation; complete results remain byte-paged artifacts. Webfetch uses external readers for public URLs; use shell for local/private downloads.
- `read_resource` accepts exactly one absolute local image `path` or an owned resource `hash`. Path reads import unchanged PNG/JPEG/WebP/GIF originals into the conversation's shared hash library, up to 50 MiB each. The next image-capable model request receives visual input; it is not automatically resent in later requests. Video frames must already be extracted.
- `GET /api/memory-config` returns `budgetMiB`, `workerMiB`, and `concurrentRuns`; `PUT` replaces all three. Bounds: total 256–1048576 MiB, Worker 128–total MiB, concurrent runs 1–128. Defaults: 2048/1024/4. About Vista offers presets and custom values. Status `capacity` contains saved configuration and actual main/Worker/MCP-host RSS. Limits apply to resident-memory admission and soft Worker/MCP-host interruption, not an OS hard ceiling or a peak forecast. Shell and external MCP subprocesses consume additional memory. Changing limits does not replay interrupted work.

MCP connections, including MCP-backed network search, are shared through a supervised host process. Configuration changes apply to new executions; existing executions and detached children retain their connection versions. Settings checks reuse hosted connections. Services may share their own browser/workspace state across conversations. Interrupted calls are not replayed automatically.
