# 前端开发

[English](./README.md)

## 入口

使用隔离的 Vista 后端。在 `web/` 安装锁定依赖，指定其回环地址并启动 Vite：

```sh
npm ci
VISTA_DEV_BACKEND=http://127.0.0.1:5186 npm run dev
```

端口使用后端实际值。开发服务监听 `127.0.0.1`，`/api` 经代理流式转发，仅改写开发页面自身的 Origin。未设置 `VISTA_DEV_BACKEND` 时 API 返回 503。浏览器只调用 Vista API，不直接请求上游模型。

| 命令 | 用途 |
| --- | --- |
| `npm run test:unit` | Node test runner 检查客户端、状态、composable 及国际化 |
| `npm run typecheck`／`npm run check` | Vue／TypeScript 检查，包含 Vite 和 E2E 配置 |
| `npm run generate:i18n` | 生成中文词条和后端回复语言名 |
| `npm run check:i18n` | 检查生成结果、词条键、占位符及消息语法 |
| `npm run build` | 生成／检查译文，构建内嵌静态站点 |
| `npm run test:e2e` | Playwright 项目，需要已构建的前端资源和 `VISTA_CHROME` |

仓库根目录的 `make test frontend` 执行单测／类型／构建，`make test e2e` 构建独立应用并执行浏览器检查。一般要求和证据边界见[验证](../docs/testing.zh-CN.md)。

## 浏览器 fixture

`e2e/frontend-fixture.ts` 通过 Vite preview 提供已构建的应用，工作进程只共享 `internal/server/assets/` 中的只读文件。
`scripts/e2e-setup.ts` 在每次 Playwright 运行前构建一次独立的控件契约页面，产物位于被忽略的 `web/.vista/test-state/controls/`，不进入应用发布产物。
每个工作进程有独立监听器，每项用例有独立浏览器上下文和可变 API fixture。
执行历史 fixture 通过监听器的 SSE 处理器保留真实流式 HTTP 响应。
仅两项渲染故障测试使用 `startSourceFrontend`，在挂载前替换源码模块。
`e2e/fixtures.ts` 中的原生服务用例继续使用独立配置和数据库，按工作进程缓存不可变的模型目录模板，CLI 启停异步执行。
`shared-fixture.ts` 每次 Playwright 运行只准备一份不可变数据；全局初始化创建新目录，结束时清理。准备失败会传递给所有使用者，不跨次复用数据。
`settings-layout-fixture.ts` 从隔离的原生实例读取当前设置响应，再通过已构建的前端验证每种语言及视口。它拒绝未收录的读取和配置／模型修改请求；保存、刷新恢复和回复语言检查继续使用原生服务。
工作进程的监听器通过 HTTP 直接返回预先序列化的 JSON 和持续的 SSE，避免大响应经过 Playwright 路由转发。设置页面的相关边界在一次浏览器执行中读取；点击、输入和异步就绪状态继续单独检查。
几何检查等待字体、渲染帧及有限动画完成；时间语义、负向观察和手势测试保留断言所需的等待。
语言和网页服务密钥流程使用减少动态效果模式；专门的动画测试继续覆盖正常过渡及偏好切换。
批量进度历史通过真实 Server／Worker 生成一次，不叠加人为模型延迟；确认 105 次工具执行、106 次模型调用成功后停止实例。每个视口恢复独立数据库及工具输出，并重定位托管路径，不复制进程身份或运行时锁；持久化、分页、完整正文、滚动和刷新检查继续走原生服务。
首轮保留失败截图和错误上下文，不持续记录 DOM／网络 trace。
失败用例再执行一次，记录含 DOM 快照、源码、网络记录和附件的 trace，不录制截图时间轴；即使这次诊断重跑通过，也保留 trace。
`failOnFlakyTests` 确保首轮失败后整条命令仍不通过。重跑不能补录原始故障过程；CI 同时保留首轮截图／错误上下文及单独的重跑 trace。
调查偶发故障时，可用 `--trace=retain-on-failure` 记录原始执行过程。
多页面流程将接收操作的页面切到前台；其他页面继续验证跨标签更新。

## 静态构建与加载

`index.html` 是 Vite 应用入口，产物是 `internal/server/assets/` 中的完整静态站点，由 Go 整目录内嵌。
同一份产物也可由静态服务器托管，配合页面路由回退及同源 `/api`、`/licenses` 反向代理；后端接受任意 Host 和 Origin，并提供允许携带凭据的 CORS。部署访问限制由运行环境或反向代理承担。
浏览器通过同源 `/api` 请求后端。
设置和会话管理按路由加载，统计图表在打开使用情况时加载。
首次挂载前加载实际语言及英文回退词条，后续切换在加载完成后生效，并拒绝被新选择取代的旧结果。
`src/i18n/catalogs.ts` 仅供检查和测试整合全部词条，浏览器使用 `loaders.ts`。
Ark 子组件使用具名导入，使构建器可以移除未使用的部分。

资源文件名包含内容哈希，并使用不可变缓存；HTML 通过 `no-cache` 和 ETag 校验更新。
Vista 返回未压缩的资源，部署时可在反向代理层配置响应压缩。
缺失的分块返回 404，不回退为 HTML。
按需加载失败会保留当前页面和编辑器，刷新需明确确认；保存在浏览器中的消息文字草稿会恢复，未保存的设置和图片附件需要重新填写或选择。

## 状态与界面边界

| 层次 | 入口 |
| --- | --- |
| HTTP／SSE 客户端 | `src/client/types.ts`、`vista.ts`、`sse.ts` |
| 全局状态同步 | `src/client/workspaceSync.ts` |
| 会话初始化／恢复 | `src/client/conversationSync.ts` |
| 事件状态 | `src/state/conversation.ts`、`workspace.ts`、`runTrace.ts` |
| 会话加载／发送 | `src/composables/useConversation.ts` |
| 共享工作区、模型、状态订阅 | `src/composables/useWorkspace.ts` |
| 服务商设置／历史执行 | `src/composables/useProviderSettings.ts`、`useRunHistory.ts` |
| 欢迎页／会话共用输入 | `src/ConversationSender.vue` |
| 上下文估算／压缩 | `src/ContextCompaction.vue`、`ContextStatus.vue` |
| 路由及弹框布局 | `src/pages/`、`src/WorkspaceModal.vue`、`src/App.vue` |

设置和管理器通过命名路由视图覆盖会话，打开时 SSE 继续工作。手机设置先显示分类目录，再进入分类页；返回按此层级逐级退出，桌面保留设置侧栏。

`meta.workspaceOverlay` 标识共用同一弹框的路由，`WorkspaceModal.vue` 用此稳定标识保留切换设置 tab 时的框架，不依赖按需加载前后的组件对象。

`ui/Modal.vue` 负责 Ark 弹窗的生命周期、焦点、遮罩和底部操作；`ui/ModalHeader.vue` 提供共用的无障碍标题、操作区及关闭控件。关闭按钮旁的操作使用 `header-actions` 插槽，`title` 插槽只放标题内容。`WorkspaceModal.vue` 在路由弹窗框架内复用此标题栏，并负责移动端返回和路由退出动画。页面提供标题、标签和操作，不再重写弹窗标题栏。`closeDisabled` 保留并禁用关闭控件，`closable` 控制其显示；全屏编辑的退出按钮也放入同一操作插槽。

切换会话中止旧请求，并用代次拒绝迟到回调。事件序号用于 SSE 重放去重及快照合并；过时快照不能覆盖更新的标题、执行和待答复状态。

核心初始化使用一致的 `/snapshot`，辅助读取失败不阻塞订阅。
SSE 记录的接续边界和独立校验点用于验证已应用进度，不直接推进游标。
流故障、无数据超时、回到前台／恢复联网及手动重试，共用有界补读与快照恢复，保留输入区状态及历史阅读窗口。
恢复只读取持久化数据，不重发消息、不调用模型／工具，也不新增会话内容定期轮询。
`RenderGuard.vue` 隔离执行详情错误，`MessageMarkdown.vue` 在格式化失败时保留纯文本。
超时和归属约束见[同步契约](../docs/architecture.zh-CN.md#会话同步)。

工作区另外共用一条通过 fetch 建立的 SSE 状态流。
组件通过 `workspace.stateSync` 订阅变化，不单独建立状态流，也不定时查询状态。
连接级订阅 ID 支持通过合并的 `PUT /api/events/subscriptions` 更新关注主题和时区，无需重连或重拉工作区信息。
`useStateQuery.ts` 按修订号缓存、取消并按需读取技能列表和选模统计；列表更新不会替换技能编辑草稿。`SkillEditor.vue` 使用 `ui/Tree.vue` 浏览现有文件，按路径保留草稿，保存选中的 UTF-8 文本时校验 SHA-256 修订号，放弃草稿前要求确认。打开期间共用状态流的技能修订仅更新目录元信息，文件正文与图片预览独立按需读取。系统技能共用只读查看器，移动端在同一个弹框内切换目录和文件。
服务端为可见的存储视图合并扫描，并按订阅者时区通知统计跨小时／跨日变化。
自动更新的视图不保留常规刷新按钮；目录检查、导入读取、授权、清理及错误恢复仍保留显式操作。
变化后的会话列表／运行状态、模型、目录进度／历史、存储状态、MCP 设置、登录结果及记忆数量／容量限制，以有界数据随状态帧推送。
工作区会话列表仅含打开的会话摘要；已关闭会话的数量来自运行状态。
管理页拥有自己的分页摘要读取和会话修订号订阅，卸载时一并取消；数据库先搜索／筛选、计数和排序，再分页，不受未分页接口最多 1,000 条摘要的限制。
`usePagedList.ts` 取消被替代的页面读取、合并并发请求，并通过服务端代次／修订号判断状态通知是否需要重新读取；`ListPagination.vue` 提供共用的页码及每页 10／20／50／100 条控件。
当前页以一份快照整体替换，保留正在编辑的标题，并将批量选择限定在该页；不重新建立全局流，也不刷新无关接口。
`SessionManagerPage.vue` 将搜索、状态筛选、排序与多选工具栏及分页放在滚动列表之外；状态筛选复用工作区计数，不增加读取。工具栏支持按创建时间或最近更新双向排序，默认创建时间由新到旧，置顶始终优先。分页 `/sessions` 请求的 `sort` 参数仅接受 `created-desc`、`created-asc`、`updated-desc` 和 `updated-asc`。最近更新时间取最后一条持久化会话事件，没有事件时使用创建时间；已读、置顶、打开或关闭操作不影响该时间。仅按更新排序的页面附带 `updatedAt`，侧边栏读取及共享摘要保持原有范围和顺序。标题／信息区统一进入会话，已关闭会话先重新打开，失败时在管理页显示错误。选择模式通过覆盖整行的原生复选框点击区域实现，原处重命名复用 `InlineSessionTitle.vue`，并在编辑结束前保留展示中的行。修改搜索、筛选、排序、页码或每页条数均清空选择。
`BatchOperationModal.vue` 是通用的批量操作二级弹窗，用于确认、进度和逐项失败结果；接收操作文案、计数与结果，不负责请求或业务数据。执行期间禁止关闭，全部成功后关闭，有失败时保留结果供查看。会话批量操作在弹窗后方保留当前展示的行、分页、计数和工作进程状态；SSE 与底层分页数据继续同步。最后一次操作结束后读取当前页，再解除展示快照；部分失败也按此处理。
模型连接、MCP 与技能导入在其确认插槽内选择来源，随后通过原有的单次导入请求展示不定进度；失败后返回预览，可修正或重试。
资源清理也使用该弹窗，根据共享状态推送显示实际删除数量；HTTP 202 确认仅代表操作开始，最终存储状态推送才结束进度。
只有已知完成数和总数时才展示确定进度；不要编造逐项进度，也不要为了进度条动画拆分原子请求。
可见填充条在完成数量变化时平滑过渡，并遵循减少动效偏好；原生进度元素保留无障碍数值。
只有实际失败条目或整批 `error` 才显示失败结果；`failureSummary` 只是文案，不是失败标志。成功关闭弹窗时，退出动画期间保持进度内容稳定。
HTTP 初始化和 SSE 更新必须采用相同的视图范围；同时检查返回内容、字节数和请求次数。
订阅从最新的匹配数据初始化，并将自身的同步操作串行处理；组件不要为同一订阅另加一次挂载读取。
初次／重连校准、缺少或过大的数据及有界内容分页继续使用普通 HTTP。
共享登录更新只包含结果；授权链接／设备码通过对应登录单独读取。
个性化中的记忆管理使用二级弹框，列表分页显示有界预览，完整内容在同一弹框中编辑。组件仅在打开时订阅及读取所请求的页面；记忆状态帧只含数量和容量限制，不含正文。分页修改响应直接更新列表，不因通知回送而重复读取。远端更新保留正在编辑的草稿，以及用于并发冲突检查的编辑／删除目标原文。
`StatisticsSettings.vue` 通过 `useStatistics.ts` 仅在挂载时读取／缓存有界的 7／30／90 天图表历史，共用流携带统计修订号而非图表载荷；切换周期及重连时拒绝被取消或过时的响应。`client/activity.ts` 合并实际的可见页面输入分钟，不报告页面闲置，也不在其他视图中读取统计。
`StatisticsTrend.vue` 将趋势图的比例尺、自适应坐标轴、SVG 渲染及指针／键盘导航交给 TanStack Charts；选中日期仍由应用管理，热力图继续使用七乘 24 个可访问控件组成的网格。
打开的模型 HTTP 页签通过同一条流接收已保存记录的摘要和修订号覆盖范围；正文按需读取，新增记录保留当前选择。
应用会话列表时按其携带的各会话事件边界合并，防止迟到的全局帧覆盖较新的会话状态或发送回执。
未变化的检查点不触发读取，也不重复发送状态数据。
成功的操作回执直接更新当前界面，共享视图通过主题通知同步，不额外刷新一次工作区。
会话元数据变化只推送列表，运行生命周期变化同时推送状态，模型／工具进展继续走会话事件流。
全局流重连后核对当前订阅状态，会话流继续使用持久游标回放。
调试指标按需推送；本地耗时显示的计时器不参与网络同步。

主模型正文作为消息区独立行，与执行过程分离。`main-outputs` 提供历史索引，可见行加载全文；正式答复通过 `outputTurn` 接替对应行，不重复展示。推理、工具和子任务活动按时间顺序直接展示为次要执行消息。`RunTrace.vue` 与 `TraceSteps.vue` 保持统一的时间顺序，不再分组折叠智能体。工具调用展示可点击的图标、操作和目标，结果默认收起，点击后原处展开。展开时按需补读缺失的完整内容，并使用有界缓存；展开状态和缓存结果在虚拟行卸载、重挂后保留。子任务报告仍通过明确操作有界读取。只有调用次数或整轮失败不产生空过程面板，整轮诊断在消息区展示。

`ConversationExecution.vue` 在输入框上方展示当前动作、耗时和最近活动。本地显示时钟使用一致性会话快照与持久事件中的时间戳，不做轮询；子任务活动更新最近活动时间，不替换主任务动作。

`ConversationChecklist.vue` 在执行期间于输入框上方展示最新任务清单，位于虚拟化消息历史之外。会话状态独立保留清单，不受最近事件窗口淘汰影响；初始化和恢复快照补入主智能体的最新清单，即使它早于最近事件页。完成、失败或中断后，清单移出输入区，在历史中显示普通可复制文本：完成数量，以及带状态的编号条目；无最终文字回复时也保留。时间与显示位置取自主智能体最后一次清单更新；仍未结束的项目取本轮停止时间和位置。消息分页在 `run_finished` 处投影最新主智能体 `checklist`，与回复共用分页游标，同时保留更新序号以独立排列显示行，不增加模型历史或额外持久事件。更新复用会话事件流，不额外读取执行概览或轮询。新执行不继承旧计划；历史清单保留原始状态，未完成项目显示为未完成／已中断，不自动标记完成。

`useConversationHistory` 以每批 20 条消息的内部准备批次扩展同一条连续列表，不提供翻页控件。
每批先准备输出索引、完整消息正文和执行索引，再发布到列表；完整正文读取最多四路并发。
`conversationTimeline.ts` 按稳定键和事件序号合并消息与单个执行步骤，由唯一的 `@tanstack/vue-virtual` 实例统一管理布局、测量、向前补载时的锚定和滚动。
只挂载可见行及预渲染行；准备滚动目标时临时增加一个有界窗口。执行数据源独立于虚拟行保留索引，`TraceSteps.vue` 不再使用嵌套虚拟列表。
已加载的消息索引保留两端，向前阅读不会挤掉最新回复。
模型输出正文使用独立的 32 项、约 8 MiB 展示缓存；当前挂载的内容可超出缓存预算，正文不会因此截断。回收会释放同步状态里的完整正文副本，保留索引和已测高度。
返回已回收的正文时重新读取，并在完整文字就绪前保留原有高度。工具输出使用 `useFullOutput` 的另一份缓存，具有相同的项数和文字预算。
`useFullOutput` 使用 TanStack Vue Query 按快照键复用 HTTP 读取、合并并发请求，并管理取消与加载／错误状态。最后一个查看者离开时取消未完成读取；按项数和文字预算回收未使用的正文，打开的内容保持完整。`client/queries.ts` 关闭焦点／重连触发的自动重取及自动重试，这些时机继续由 SSE 和明确的重试操作决定。
拖动原生滚动条、触摸移动及滚轮／键盘滚动期间，HTTP 和 SSE 继续更新同步状态，展示变更与新测量暂存。
仅首次进入会话时隐藏正文并显示整块消息区的加载指示。滚动进入尚未准备好的区域时，暂时锁在最后可读的稳定键位置，保留正文，在顶部显示一个加载指示。
同一个虚拟列表在视口外准备并测量有界的目标窗口，完成后移到用户请求的稳定键位置并解锁。加载期间滚轮、触摸、键盘和原生滚动条不能移动已停住的视口；固定滚动条槽位保留正文宽度。
仅预渲染区的准备不会触发加载。返回缓存已回收的展开结果时，其读取加入滚动准备；主动展开仍保留行内加载和重试操作。向前读取历史时也使用顶部加载指示，保留正在阅读的内容。准备期间 HTTP 和 SSE 继续接收数据。
`useConversationScroll` 将所有滚动写入交给 TanStack，并在 DOM 提交后完成布局更新，使此前受旧占位高度钳制的底部修正能完成。
手势控制只在输入和滚动事件稳定后结束，虚拟列表的布局通知不能结束手势。触摸跟踪原始目标，确保虚拟行被回收、移出 DOM 后，结束／取消事件仍能释放暂存更新。
内容和视口变化保留跟随／阅读模式。滚轮、触摸、键盘、滚动条和查看执行详情可取消未完成的跳转；到达底部、发送消息或点击唯一的“回到最新消息”恢复跟随。
权威快照恢复期间保留已浏览的历史前缀与阅读位置，待替换数据准备完成后更新。图片下载前预留布局，展开内容的缓存重新读取时保留已测高度。

稳定选中文字 350 ms 后提供引用追问，拖动／选区变化、复制、滚动或 Escape 收起。引用草稿按会话保存，发送时作为 Markdown 与问题共用普通输入链路，包括插话和排队。合并后的消息仍受 8 KiB 输入上限约束，失败保留完整草稿。编辑和撤回共用[会话回退约定](../docs/message-revert.zh-CN.md)。

`src/ui/` 维护 Vista 的展示组件。Ark UI 提供弹窗、选择框、菜单、开关、滑杆、分页、折叠内容和工作区分栏的交互与无障碍基础；普通按钮、文本输入、消息气泡和发送区使用原生元素。会话状态、渲染窗口和发送逻辑仍由现有状态层与组合式函数管理。`@tabler/icons-vue` 按需提供 SVG 图标，共享 CSS 使其尺寸随周围字体调整。

`src/ui/appearance.ts` 保存 `vista-appearance` 并同步同源标签页；语义颜色和控件尺寸位于 `src/ui/tokens.css`，共享组件样式位于 `src/ui/components.css`。启动时先于样式应用主题；动效跟随 `prefers-reduced-motion`，包括组件动效、CSS 过渡／动画及 JavaScript 平滑滚动。

键盘导航保持启用。输入框未将 Tab 用于补全时，Tab 用于切换焦点；保留文字编辑、输入法、发送快捷键和 Esc。 普通 Enter 直接提交；正在合成、`isComposing` 和键码 229 会阻止候选确认误发。Enter 不再使用合成结束后的时间保护窗口。草稿在 Vista 接受请求后清空，不等待上游模型成功。
导航指示使用 `:focus-visible`，不能仅因鼠标／触屏聚焦就显示键盘焦点框。
`AppProvider` 使用 Ark UI 跟踪交互方式，焦点轮廓统一使用 `--focus-outline`，使鼠标／触屏操作后的焦点恢复不误亮，同时保留键盘和辅助导航的提示。

文字操作使用共享 `Button` 的默认 36px 高度，包括列表操作及确认气泡；不使用 `small`，也不通过局部 padding、高度或字号覆盖缩小。图标按钮使用 `.icon-button` 和统一的 `--button-icon-size`：桌面端 32px，宽度不超过 830px 或粗指针设备上为 44px。发送控件、消息操作、图片预览关闭和侧栏导航保留专用布局。

空状态使用 `src/ui/Empty.vue` 的共享图示，通过 `.vista-empty-state` 统一间距和字体；窄侧栏使用 `.vista-empty-state-compact`。加载中和错误状态与空结果分别呈现，保留各场景的提示文案，没有结果时隐藏分页控件。

`TraceToolResult.vue` 通过 `FileDiffOutput.vue` 展示 `write_file` 及多文件 `apply_patch` 的差异产物。
差异记录已经提交的当次写入，不跟随当前文件内容变化；`RunToolOutput.vue` 在请求完整结果时通过现有的限量输出缓存加载它。

分别展示新建、内容未变及差异不可用状态，并兼容旧历史中只有元数据的写入结果。

## 共享配置编辑器

`src/SchemaForm.vue` 负责纯表单草稿及 JSON Forms／Ajv 校验，不再提供 JSON 原文编辑或模式切换。 必填星号和 `aria-required` 表示必须填写内容，而非仅要求对象属性存在：允许空值的字符串及允许关闭的开关不标必填，Schema 仍保留类型和属性存在性校验。`src/schema/` 将标量、枚举、对象、有序列表和只写密码输入映射到 Vista 控件；无效字段值保留在本地并阻止保存。父视图负责显式保存及类型化 API 请求。 容量预设使用独立的 Schema 草稿选择器：选择后一次填入三项数值，不自动保存，也不持久化预设标识；手动数值保留“自定义”状态。业务页面负责分组次序及相邻说明图，UI Schema 声明组内控件。 UI Schema 枚举控件可通过 `enumGroups` 复用原生下拉分组，通过 `enumFullLabels` 保留收起后的用途上下文；渲染器不识别具体服务商名称，也不改变底层枚举值。固定服务优先级列表使用 `reorderOnly`，不提供逐行替换服务的枚举下拉。草稿比较忽略对象键次序，但绝不排序数组。Ajv 错误按关键字本地化，带字段路径的业务问题通过 JSON Forms additional errors 标到实际控件，提供具体文案、ARIA 关联及可见错误边框。共享字段前／后插槽让说明保持相邻，不让通用渲染器识别业务字段名。

适配器提供独立的只写凭据输入草稿，以及 `config.json`（`version: 2`）七个分区中可编辑的公开设置；智能体编辑器还包含独立的全局 `AGENTS.md` 提示词。静态凭据位于 `key.json`（`version: 1`），因此固定用户文件名为三个，而不是七个 JSON 文件加提示词。其中 `entries` 将不透明引用映射到 `{section, owner, values}` 凭据包；受管模型／MCP 记录或搜索对象在主文档中携带 `credentialRef`。归属使用稳定身份，不取自显示名称或列表位置；UI 适配器不自行构造归属字符串。分区用途、凭据字段及迁移来源见[配置编辑](../docs/product.zh-CN.md#配置编辑)。仓库中的 Schema 和适配器属于源码，并非运行时配置文件；缺失分区沿用原有默认值或环境变量回退，显式空值／`null` 保留各自的类型化语义。

表单草稿绝不包含完整 `config.json`、`version: 2`／分区外壳或 `key.json`。凭据输入草稿仅含已保存秘密的空占位和用户明确输入的新值；只写渲染器对其遮罩，既有类型化适配器继续负责复用／清除规则。例如，服务配置草稿为 `{"port":6186}`，保存在 `config.json` · `server`，不是 `{"version":2,"server":{"port":6186}}`。模型静态字段 `apiKey`／`accessToken`／`authToken`／`appCode`／`headers`、MCP 的 `token`／`clientSecret`／`headers`，以及搜索的 `apiKeys`／`jinaApiKey`／`deepseekFetchApiKey` 属于私密凭据包。整个自定义 `headers` 对象保守迁出，不限于已识别的认证请求头。公开的 `clientId`、路由和身份设置保留在主文件。

两份 JSON 在 Unix 上仍是 `0700` 配置根目录内的 `0600` 私密文件。这是明文文件隔离，不是加密、系统密钥环、云 KMS 或同一用户身份下进程之间的安全边界。主文件仍可能暴露内部地址、项目／账号标识，不能直接认定适合公开分享。`AGENTS.md` 仍与 JSON 分开保存。技能、SDK 账号／刷新令牌／登录授权数据、生成的模型目录文件和 SQLite／运行状态不计入三个固定文件；不重新设计授权，也不迁移 OAuth／登录令牌。启动迁移不覆盖提示词，也不恢复旧账号身份。

一次性转换仅属于 Server 启动，先取得实例锁，再在应用设置加载前处理：没有主配置时才接受七个旧 JSON 文件，或升级此前内联的统一 v1。先校验并准备转换，保留并校验覆盖实际来源的私密逐字节备份及 `SHA256SUMS`（包括适用时的 v1 主文件／已有密钥文件），先发布密钥、后发布主文档引用，校验已发布的双文件及所需持久化后，再仅移除未变化的旧版来源原文件。私密备份继续保留，不自动恢复。已有当前主文件后，后续启动仅作校验：健康启动不扫描旧路径、不导入旧数据，也不新建迁移备份；遗留旧文件会被忽略，即使某分区缺失也不例外。

正常读写仅使用当前 `config.json` v2 和 `key.json` v1，不回退旧数据或旧凭据。库及首次写入均不迁移；正常访问旧版或尚未迁移的数据时，会提示“启动 Vista 以迁移”（“start Vista to migrate”），而不是复制旧值。全新空根目录内的显式写入可以初始化当前文件，但不转换旧状态。

服务商选择、模型发现、OAuth、导入及私密凭据控件保留在 JSON 草稿之外。现有类型化 API 在内部解析私密凭据包，保留既有脱敏、留空复用及显式清除语义。不得暴露已保存的凭据，也不得将 GET 返回的脱敏密码／请求头值写回文件。保存继续使用这些类型化 API，不提供任意文件系统写入接口或凭据文件编辑器。预览限制按 UTF-8 字节数计算，0 表示不限制。

父视图传入的值变化时，保留本地表单草稿及无效字段值；重新载入当前值前，须确认丢弃草稿。这种本地过期草稿处理不代表所有 API 都支持 CAS；只有服务配置使用服务端对紧凑 `server` 分区计算的 SHA-256 修订号，其他分区写入不会导致冲突；其余适配器保留原有类型化接口的保存语义。共享存储通过 `state/config.lock` 串行化主配置／密钥文档写入，在最新主文档中更新目标分区，保留其他分区和凭据。先暂存新的不可变密钥引用／条目并保留旧条目，再发布主文档引用，最后仅移除本次已提交更新放弃的此前活动引用。每次替换各自原子，但两份文件不是一个原子事务；已有的无引用／中断遗留条目不会被盲目回收，不承诺安全擦除或自动清理／恢复旧身份。

存储读取在复用已解析内容前核验当前私密字节及 SHA-256，包括保留元数据的编辑。含密钥分区读取在读取密钥后再次检查主快照，遇到发布／裁剪竞态则重试；稳定快照中的无效／缺失引用按失败关闭处理，不回退旧密钥。已有主文件是唯一来源，旧版二进制不得使用已迁移目录。非密钥分区读取不逐请求加载密钥文件。经确认的完整重置保留共用写入锁，Unix 目录同步仍是发布持久化的一部分。这些均不为直接编辑文件新增全局热加载。现有类型化 API 保存保留运行时效果，智能体／UA 保留直接读取边界，缓存的模型／MCP／搜索／容量设置保留既有重新加载／启动要求。用户确认的端口修改是例外：「保存并重启」先由新实例预占目标端口，再保存并返回新地址；旧标签页使用有时限的就绪图片检查并提供新标签页入口。端口错误采用独立代号，不冒充修订冲突。已保存的端口仍与实际监听端口分开，优先级为 CLI `--port` > `VISTA_PORT` > 当前 `server.port` > 默认值；常规 WebUI「重启 Vista」保留实际端口。CLI 可以在重启前只读检查启动端口输入以作校验，不写配置、不迁移，也不将已保存／默认端口合成为显式 `--port`。实际启动端口由 Server 在迁移或当前格式校验后解析；WebUI 重启时保留运行端口，与提升已保存／默认值不同。见[存储约定](../docs/architecture.zh-CN.md#统一配置存储)。

## MCP OAuth 回调提交

`MCPSettings.vue` 通过 `POST /api/mcp-servers/{id}/login` 启动授权，再用 `GET /api/mcp-auth/{id}` 读取该次授权链接。
打开或复制链接，在浏览器完成授权。授权后浏览器连接失败属于预期情况：复制地址栏中的完整回调 URL，回到 Vista，在弹框内粘贴并提交。
授权 5 分钟后过期；关闭弹框通过 `DELETE /api/mcp-auth/{id}` 取消授权，迟于关闭返回的启动结果也会被取消。
请勿将回调 URL 粘贴到聊天或日志中。

只有 `pending` 可提交：向 `POST /api/mcp-auth/{id}` 发送 JSON `{ "callbackUrl": "完整 URL" }`。
HTTP 200 返回 `status=exchanging` 且 `authorizationUrl` 为空的 Login；HTTP 400 保持 pending，可修改输入后重试；HTTP 409 表示尚未就绪、已提交或已终止，界面会单独读取该次授权以恢复状态。
`starting`、`pending` 和 `exchanging` 均为活动态；请求发送中及 exchanging 阶段禁止重复提交，但仍可取消。
共享 MCP 登录更新仅含 `id`、`status` 和可选 `error`，不携带授权链接或回调 URL。
尝试 ID、代次、读取修订号及只前进的状态共同拒绝迟到响应，防止先到的 SSE 终态被后到的 POST 回执倒退。
完成状态直接使用共享推送，不额外读取配置或登录状态。

回调输入最多 8,192 个字符，仅保存在组件内存，关闭自动填充和拼写检查。
取消、重新授权、卸载、提交被接受、进入 exchanging 及终态时清空；请求或输入校验出错且仍为 pending 时保留。
界面只将它放入 Vista API 请求体，不打开或请求该 URL，不写日志或浏览器存储。
